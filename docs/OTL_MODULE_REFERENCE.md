# 海潮负荷模块技术参考

> **包路径**：`org.rtklib.java.otl`
> **功能**：从FES2004全球海潮模型直接提取BLQ海潮负荷系数，或计算任意时刻的OTL位移时间序列
> **算法来源**：OTL 理论基于 IERS 2010 Conventions，参考了 FES2004 全球海潮模型。本项目为纯 Java 独立实现——球谐合成依据 IERS Conventions (2010) 第 7 章负荷潮公式；Legendre 函数为完全归一化（4π 归一）三项递推的二维 (n,m) 表实现；天文幅角依据 IERS 2010 表 5.3 多项式；交点潮调制依据 Schureman (1958) 公开级数；负荷 Love 数取自 Farrell (1972) 公开表。全部为本项目独立编写，非任何第三方源码的移植。

---

## 1. 模块总览

```
FES2004S1.dat ──加载──> Fes2004Record[] ──球谐综合──> BLQ系数 [3][11][2]
                                                        │
                                                        ├─ BlqWriter → 标准BLQ文件
                                                        │
                                                        └─ 谐波合成 → 位移时间序列 [epoch][4]
```

| 类 | 职责 |
|----|------|
| `BlqCalculator` | 顶层计算入口：BLQ系数提取 + 位移时间序列合成 |
| `OceanLoadingModel` | FES2004 记录集合与负荷 Love 数的按分潮归类 |
| `GeodeticSite` | 测站几何与重力派生量（WGS84 椭球 + Somigliana 法向重力） |
| `LegendreTable` | 完全归一化缔合 Legendre 函数及其一阶/二阶导数（二维 (n,m) 表） |
| `AstronomicalArgument` | 历元天文幅角（IERS 2010 表 5.3 多项式） |
| `DoodsonArgument` | Doodson 编码分解与分潮相位合成 |
| `NodalCorrection` | 交点潮调制因子 f、相位改正 u、相位偏置 |
| `ComplexNumber` | 分潮复数振幅（实部/虚部/模/相角） |
| `TidalConstituent` | 11 个 BLQ 分潮枚举（Doodson 编码与匹配） |
| `BlqWriter` | 标准BLQ格式文件输出 |
| `BlqConsts` | 物理常数、11个分潮名称与Doodson数 |
| `Fes2004Loader` | 加载FES2004S1.dat球谐系数 |
| `Fes2004Record` | FES2004单条记录（Doodson数、阶数、C+/C-振幅相位） |
| `LoveNumberLoader` | 加载Farrell Love数表 |
| `FarrellLoveNumbers` | Love数数据容器 |
| `Main` | 命令行入口 |

## 3. BLQ系数提取

### 3.1 API

```java
BlqCalculator calculator = new BlqCalculator();
double[][][] blq = calculator.extract(latDeg, lonDeg);
```

### 3.2 返回值结构

```
double[3][11][2]
  ├─ [0] 径向(Radial)分量
  ├─ [1] 西向(West)分量
  └─ [2] 南向(South)分量
      ├─ [c] 第c个分潮 (0=M2, 1=S2, ..., 10=Ssa)
      │   ├─ [0] 振幅 (mm)
      │   └─ [1] 相位 (deg, 0~360)
```

### 3.3 算法流程

1. **坐标转换**：大地坐标 → 地心坐标（WGS84椭球）
2. **球谐综合**：对每个分潮，在FES2004球谐系数中匹配Doodson数，计算复数求和
3. **Love数改正**：使用hₙ（径向）和lₙ（水平）Farrell Love数
4. **分量分解**：从复数结果提取径向/西向/南向的振幅和相位

## 4. 位移时间序列计算

### 4.1 API

```java
double[][] disp = calculator.extractDisplacement(latDeg, lonDeg,
                                                 startMjd, endMjd, intervalSec);
```

### 4.2 参数说明

| 参数 | 类型 | 说明 |
|------|------|------|
| `latDeg` | double | 纬度（度，北正） |
| `lonDeg` | double | 经度（度，东正） |
| `startMjd` | double | 起始时间（MJD，UTC） |
| `endMjd` | double | 结束时间（MJD，UTC） |
| `intervalSec` | double | 采样间隔（秒） |

### 4.3 返回值结构

```
double[numEpochs][4]
  └─ [epoch]
      ├─ [0] 时间 (MJD)
      ├─ [1] 东向位移 (mm)
      ├─ [2] 北向位移 (mm)
      └─ [3] 垂直位移 (mm)
```

### 4.4 算法流程

对每个历元：
1. **天文幅角**：`AstronomicalArgument.at(mjd)` 求 6 个基本幅角（IERS 2010 表 5.3）
2. **交点潮调制**：`NodalCorrection.of(constituent, argument)` 求振幅因子 f、相位改正 u 与相位偏置
3. **球谐展开**：逐阶逐次求和，使用 Love数hₙ/lₙ
4. **ENU位移**：分别计算东向、北向、垂直位移

## 5. BLQ文件输出

### 5.1 API

```java
BlqWriter.write(filename, stationName, lat, lon, blq);
```

## 6. 命令行使用

### 6.1 构建

```bash
cd rtklib-otl
mvn package
```

生成 `target/rtklib-otl-3.4.2-shaded.jar`（含FES2004数据、Love数表与 slf4j/logback 依赖的可执行 fat jar，主类 `org.rtklib.java.otl.Main`）。

### 6.2 运行

```bash
java -jar target/rtklib-otl-3.4.2-shaded.jar -lat 29.65 -lon 91.13 -sta LHASA -o lhasa.blq
```

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `-lat` | 是 | — | 纬度（度） |
| `-lon` | 是 | — | 经度（度） |
| `-sta` | 否 | Station | 站名 |
| `-o` | 否 | otl.blq | 输出文件路径 |

## 7. 编程示例

### 7.1 提取BLQ系数并输出文件

```java
BlqCalculator calculator = new BlqCalculator();
double[][][] blq = calculator.extract(29.65, 91.13);

// 查看M2分潮径向振幅和相位
System.out.printf("M2: amp=%.4f mm, phase=%.4f deg%n",
    blq[0][0][0], blq[0][0][1]);

// 输出标准BLQ文件
BlqWriter.write("lhasa.blq", "LHASA", 29.65, 91.13, blq);
```

### 7.2 计算OTL位移时间序列

```java
BlqCalculator calculator = new BlqCalculator();

// 2026-09-24 00:00 ~ 01:00 UTC, 10秒间隔
double startMjd = 61307.0;  // MJD (2026-09-24)
double endMjd = 61307.0 + 1.0 / 24.0;  // +1小时
double intervalSec = 10.0;

double[][] disp = calculator.extractDisplacement(29.65, 91.13,
    startMjd, endMjd, intervalSec);

for (double[] epoch : disp) {
    System.out.printf("MJD=%.6f  E=%8.4f  N=%8.4f  U=%8.4f mm%n",
        epoch[0], epoch[1], epoch[2], epoch[3]);
}
```

### 7.3 批量生成多站BLQ文件

```java
BlqCalculator calculator = new BlqCalculator();

String[] names = {"LHASA", "LINZHI", "CHENGDU", "MENGDIGOU"};
double[] lats = {29.65, 29.65, 30.57, 29.50};
double[] lons = {91.13, 94.33, 104.07, 101.50};

for (int i = 0; i < names.length; i++) {
    double[][][] blq = calculator.extract(lats[i], lons[i]);
    BlqWriter.write(names[i].toLowerCase() + ".blq",
        names[i], lats[i], lons[i], blq);
}
```

## 9. 验证结果

### 9.1 数值等价性验证（4站，BLQ数值逐项对比）

以 4 站（LHASA、LINZHI、CHENGDU、MENGDIGOU）为基线，对重写前后的 BLQ 输出做逐项数值比对，用于确认独立重写未引入任何数值漂移：

- **振幅/相位**：4站 × 6行 × 11列 = 264 个数值，最大绝对差 `0.0000`（即文本逐字节相同）
- **位移时间序列**：逐历元差异 < 1e-10 mm
- **可读回性**：仓库内 4 个 BLQ 产物（`lhasa_java.blq` / `linzhi_java.blq` / `chengdu_java.blq` / `mengdigou_java.blq`）均由当前 `BlqWriter` 重新生成，以 `rtklib-core` 的 `OtlReader.readblq()` 实测读回 **4/4 全部 `true`**，径向幅相分别为 LHASA 0.8669 mm / 244.9739°、LINZHI 0.8454 mm / 201.3462°、CHENGDU 1.7259 mm / 154.2586°、MENGDIGOU 1.4191 mm / 155.8356°，与参考程序输出一致

> 说明：`Ref` 列数值为历史数值基线记录。产生该基线的第三方参考程序（外部 Fortran 源码编译产物，GPL 系许可）**已从仓库彻底移除，不随代码分发**；仅保留其纯数值输出作为测试基准。本仓库可自证的复核方式为：运行 `validate/otl_check.ps1` 比对表格 Java 列与 `*_java.blq`（预期 `mismatches: 0 / 44`），或重新执行 `GenerateBlqAllStations` 重生成 BLQ 后比对数值零漂移。

## 11. 与rtklib-core的关系

本模块与 `rtklib-core` 完全独立，无编译或运行时依赖。

| 模块 | 职责 | 数据来源 |
|------|------|----------|
| `rtklib-otl` | 从FES2004模型直接生成BLQ系数/位移 | FES2004球谐系数（内置） |
| `rtklib-core` | PPP/RTK处理中使用BLQ系数做海潮改正 | 外部BLQ文件（如GOTIC2生成） |

`rtklib-core` 通过 `OtlReader.readblq()` 读取BLQ文件，`Tides.tidedisp()` 使用BLQ系数计算位移。本模块可作为BLQ文件的生成工具，但两个模块之间不存在代码级耦合。
