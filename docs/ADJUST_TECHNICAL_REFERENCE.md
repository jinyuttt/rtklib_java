# rtklib-adjust 技术参考

## 1. 模块定位

本模块在**结果空间**对多条独立RTK基线做间接平差，属于"后验融合"类方法。

它**不是**观测层联合解算（统一Kalman滤波），不修改rtklib-core的解算流程。

### 1.1 核心价值

多基线融合解决的是**可靠性**问题，不是精度问题：

| 价值 | 优先级 | 本模块支持 |
|------|--------|-----------|
| FIX可用性提升 | ⭐⭐⭐⭐⭐ | ✅ 至少一条FIX就输出结果；可选 `allowFloat` 让 FLOAT 补位（实测出解覆盖率 90.8% → 100.0%） |
| 假固定检测 | ⭐⭐⭐⭐ | ✅ σ₀检验 + Baarda T |
| 粗差基线剔除 | ⭐⭐⭐⭐ | ✅ Baarda数据探测 |
| 服务范围扩展 | ⭐⭐⭐ | ✅ 多基站覆盖 |
| 定位精度提升 | ⭐ | ✅ 但改善<1%（短基线） |

**定位精度改善<1%的原因**：各FIX解差异已在毫米级，残余误差主要是Rover端公共多路径——对公共误差取平均不会减小它。

### 1.2 模块边界（架构定论）

本模块的链路只有两段，**与 rtklib-joint 没有接口关系**：

```
rtklib-core（SBS：单基线独立 Kalman 滤波，每个基站一条）
        ↓  逐历元 SolData（FIX 基线解）
rtklib-adjust（网平差：结果空间）
        ↓  平差坐标 / 精度评定 / 基站位移
项目成果
```

| 模块 | 作用 | 说明 |
|------|------|------|
| rtklib-core | SBS 解算 | 一个基站一条基线各自独立滤波；k 个基站 → k 个 FIX 解 |
| rtklib-adjust | 网平差（本模块） | 只做结果空间平差，不产生观测、不改 core |
| rtklib-joint | MBS 引擎 | **与 core 同层**的另一个 RTK 引擎，独立闭环，不接本模块 |

**joint 无法接入本模块的原因**：joint 在观测层把 k 条基线的双差方程并进同一个滤波器、一次解算，输出时"多条独立基线解"这个中间产物已不存在；而本模块的观测值恰恰是那些独立基线解。

**定论**：`adjust = SBS（来自 core）+ 平差（本模块）`；`joint = 独立的 MBS 引擎`。

### 1.3 FLOAT 补位（`allowFloat`，可选）

历史行为是"只吃 FIX"：某历元若两条基线都未固定，该历元直接断档、无输出。开启 `allowFloat` 后，FLOAT 基线可作为补位观测进入平差，把**出解覆盖率**从 ~91% 提到 100%（实测 228/251 = 90.8% → 251/251 = 100.0%，另一场景 228/248 = 91.9% → 248/248 = 100.0%）。

规则（详见 §2.5）：

- **FIX 优先**：FIX 达到 2 条及以上时 FLOAT 一律丢弃——双 FIX 交叉验证是最可靠判据，掺入分米级 FLOAT 只会把基线间较差推过 `SUSPECT` 阈值、错误剔除真 FIX
- **FIX 不足 2 条时才补位**：0 条 FIX 时无参照物，FLOAT 直接补位；1 条 FIX 时 FLOAT 需通过"与 FIX 的位置较差 ≤ `floatAgreementThreshold`"的准入门限
- **FLOAT 协方差膨胀降权**：`floatCovInflate`（默认 1000，按方差计），融合坐标基本由 FIX 决定
- **只污染坐标，不污染基站**：基站一致性检核、网平差观测累积、基站诊断仍只消费 FIX，避免 FLOAT 分米级偏差污染基站位移与 σ₀
- **等级如实标注**：补位历元产出的是 `UNVERIFIED` 等级（零自由度），不会伪装成已验证结果

> 注意：这里的"提升固定"指**提升出解可用性**（历元不再断档），不是把 FLOAT 变成 FIX。FLOAT 补位历元的等级与保护级仍按 `UNVERIFIED` 口径给出。

## 2. 数学模型

### 2.1 观测方程

对同一历元 k 条**准入**基线（默认全是 FIX，开启 `allowFloat` 后可能含补位 FLOAT），各基线RTK解给出的Rover ECEF位置作为虚拟观测值：

```
l = H·x + v
```

| 符号 | 维度 | 含义 |
|------|------|------|
| l | 3k×1 | 观测向量，各基线给出的Rover位置 |
| H | 3k×3 | 设计矩阵，每3行为一个I₃（P3 开启后取 `hPos`） |
| x | 3×1 | 参数向量（Rover ECEF坐标） |
| v | 3k×1 | 残差向量 |

### 2.2 法方程与解

```
N = HᵀR⁻¹H          法方程系数矩阵
u = HᵀR⁻¹l          法方程常数项
dx = N⁻¹u            参数解
v = H·dx - l         残差
```

其中 H 的各块默认取 I₃（P3 开启后取 `hPos`）；R 的对角块对 FIX 基线取 `covEcef`，对**准入的 FLOAT 基线**取 `covEcef × floatCovInflate`（默认 1000，按方差计），因此 FLOAT 在法方程中的信息权重仅为 FIX 的 1/1000 量级（见 §2.5）。

### 2.3 精度评定

```
df = 3k - 3                           自由度
σ₀² = vᵀR⁻¹v / df                    验后单位权方差 (df>0)
Dx = σ₀²·N⁻¹                          参数协方差 (df>0)，否则 Dx = N⁻¹
Qv = R - H·N⁻¹·Hᵀ                     残差协因数矩阵
T_i = |v_i| / (σ₀·√Qv_ii)             Baarda数据探测统计量
```

### 2.4 特殊情况

| k | df | 行为 |
|---|-----|------|
| 0 | - | 返回失败 |
| 1 | 0 | 无法精度评定，σ₀=NaN，不计算Baarda |
| ≥2 | 3(k-1) | 完整精度评定 |

`k` 在此指**准入后**实际参与平差的基线数，`allowFloat=false` 时只计 FIX；`allowFloat=true` 时 FIX 与准入通过的 FLOAT 共同计入（见 §2.5）。

### 2.5 FLOAT 补位准入策略

准入由 `MultiBaselineConfig.SolutionAdmissionConfig` 控制，三个参数：

| 参数 | 默认 | 含义 |
|------|------|------|
| `allowFloat` | `false` | 是否允许 FLOAT 基线进入平差。`false` = 仅 FIX，与历史行为逐位一致 |
| `floatCovInflate` | `1000.0` | FLOAT 协方差膨胀倍数（**按方差计**，即 σ 放大 √1000 ≈ 31.6 倍），用于降权 |
| `floatAgreementThreshold` | `0.20` | 仅 1 条 FIX 时，FLOAT 与 FIX 的位置较差上限 (m) |

准入判定（`selectAdmitted`）：

```
FIX 条数 ≥ 2            → 只留 FIX，FLOAT 全丢
FIX 条数 = 1，有 FLOAT   → 逐个比对 |FLOAT - FIX| ≤ floatAgreementThreshold：
                            通过 → 准入（后续判级为 SINGLE_VERIFIED）
                            拒绝 → 不进入 WLS，经 AdjustResult.rejectedFloats 显式上报
FIX 条数 = 0，有 FLOAT   → FLOAT 全部补位（无参照物，门限不适用）
```

**门限前移的设计意图**：`floatAgreementThreshold` 从"事后判级"前移为**准入前置条件**，使"准入"与"等级"成为同一单调映射——较差 ≤ 阈值 → 准入 → `SINGLE_VERIFIED`；较差 > 阈值 → 拒绝 → `UNVERIFIED`。这样消除了"FLOAT 既拉坐标、等级又说不可信"的矛盾中间态。

**拒绝必须上报**：被拒 FLOAT 已不在 `admitted` 内，平差看不到；若不上报就变成静默丢弃。`AdjustResult.rejectedFloats`（`RejectedFloat(baseId, distanceToFix, threshold)`）承担这条可见性。距离口径由 `GnssBaselineAdjust.floatDistancesToFix` 单点提供，准入判定与判级共用；`fixCount != 1` 时返回空 Map，表示"无参照物"，调用方须读作"无法判定"而非"较差为 0"。

**`rejectedFloats` 的口径**：只承载"因超门限而被拒"的 FLOAT。FIX ≥ 2 时被丢弃的 FLOAT **不**进入该列表——它们不是"不可信"，而是"已被双 FIX 取代"，语义不同，不应混在一起报警。

**实测（BDS 双频，2 基站，251 配对历元）**：

| 指标 | 仅 FIX | FIX+FLOAT |
|---|---|---|
| 出解覆盖率 | 228/251 = 90.8% | 251/251 = 100.0%（+9.2 个百分点） |
| 平差历元数 | 228 | 251 |
| 等级分布 | UNVERIFIED=22, SUSPECT=206 | UNVERIFIED=45, SUSPECT=206 |

覆盖率提升全部来自"0 条 FIX"的纯 FLOAT 历元（22 个）与少量"1 FIX + FLOAT"历元（2 个），原有 206 个 SUSPECT 历元等级不受影响。代价是这 23 个历元的等级如实降为 `UNVERIFIED`。

## 3. 全局协方差矩阵 R 的构造

### 3.1 结构

默认 `rho=0`（各基线独立，core 为单基线引擎逐基站独立调用），R 为块对角阵：

```
k=1:  R = [C₁₁]                                    (3×3)

k=2:  R = [C₁₁,   0  ]                             (6×6)
           [ 0  , C₂₂ ]

k=3:  R = blkdiag(C₁₁, C₂₂, C₃₃)                   (9×9)
```

`rho>0` 时非对角块按 `R_ij = rho·sqrt(C_ii ⊙ C_jj)` 构造（近似估计）。

- **对角块 C_ii**：第i条基线的自身协方差（3×3），取自 core 输出的 `SolData.covEcef`（完整 3×3，含非对角符号），非近似值。`covEcef` 的数据源按优先级取 `Sol.qPos` → `Sol.qr`，见 §3.4
- **非对角块**：默认 `rho=0`（各基线独立，R 为块对角阵）；`rho>0` 时按 `R_ij = rho·sqrt(C_ii ⊙ C_jj)` 构造（近似估计）

### 3.2 Pr_fused 的计算

信息矩阵融合：

```
Pr_fused = (P_rover_1⁻¹ + P_rover_2⁻¹ + ... + P_rover_k⁻¹)⁻¹
```

其中 P_rover_i 是第i条基线的Rover位置协方差。

### 3.3 Pr_fused 的理论含义

Pr_fused 是"如果各基线Rover位置估计相互独立，加权融合后的最优估计协方差"。

**注意：这不是两条基线Rover位置估计之间的真实互协方差。** 真实互协方差应为Rover端公共误差的协方差，两者是不同的数学对象。详见第5节。

### 3.4 协方差数据源：`Q_pos` 与 `Pa`（core 新增形式）

core 为后处理（网平差、聚合器）新增了**第二种位置方差**，与原有 Kalman 后验协方差并存：

| 数据源 | 字段 | 数学含义 | 是否含跨历元相关性 |
|---|---|---|---|
| 单历元归约法方程 | `Sol.qPos` → `SolData.qPos` | 只由**当前历元**的双差观测归约得到的 3×3 位置协方差 | 否 |
| Kalman 后验 | `Sol.qr` → 对称展开 | 滤波状态协方差的位置块 `Pa` | 是（跨历元传播） |

**协方差的三种表现形式**（同一物理量、不同封装口径，平差只认第一种）：

| 形式 | 字段 | 元素数 | 非对角符号 | 用途 |
|---|---|---|---|---|
| 完整 3×3 行优先（**带符号**） | `SolData.covEcef` | 9：`c_xx,c_xy,c_xz,c_yx,c_yy,c_yz,c_zx,c_zy,c_zz` | **保留** | 平差/网平差/聚合器的真值来源 |
| 上三角压缩（.pos 风格） | `Sol.qr` | 6：`c_xx,c_yy,c_zz,c_xy,c_yz,c_zx` | 保留（对称展开后即 3×3） | 滤波内部状态、`Accuracy` 的源 |
| 精度摘要（**无符号**） | `SolData.accuracies`（`s1,s2,s3,c12,c23,c31`） | 6 | **丢失**（构造时取 `sqrt(|c_ij|)`） | 界面显示、.pos 输出 |

- `covEcef` 是唯一保留完整符号信息的对外形式：`CovAssembler.extractCovariance3x3` 直接按行优先装成 3×3，不做 `abs()` 也不开方
- `Accuracy` 的 `c12/c23/c31` 是 `sqrt(|c_ij|)`，符号在构造时已丢失；只有当历元无 `covEcef`（`qr[0]==0` 哨兵）时 `CovAssembler` 才回退用它重构，此时非对角只能填正值，与真实符号可能相反——这是刻意的降级路径，避免整条基线因缺协方差被丢弃
- 速度协方差 `Sol.qv`（6 值，`m²/s²`）同样是带符号的上三角形式，但平差只消费位置，不读速度

**求解方式**（`QposSolver`）：

```
A    = 扫 H 得到的活跃列集 ∪ {0,1,2}          （升序绝对列索引）
N_A  = H_Aᵀ R⁻¹ H_A
FLOAT → Q_A = N_A⁻¹，位置块取 Q_A[0:3,0:3]
FIX   → 模糊度视为已知常数，A_fix = A ∩ [0,NR)，Q_pos = (H_AfixᵀR⁻¹H_Afix)⁻¹[0:3,0:3]
        （NR = NP+NI+NT+NL，即状态向量中"模糊度之前"的维数）
```

三个关键点：

1. **FIX 不能用 `(H_posᵀR⁻¹H_pos)⁻¹`**：那是 `A_fix = {0,1,2}` 的特例。`ionoopt=EST` / `tropopt≥EST` / GLONASS autocal 启用时，电离层、对流层等状态的不确定性必须通过求逆边缘化传播到位置块；只取前 3 列会得到系统性偏小的 `Q_pos`（静默偏乐观）
2. **扫 H 而不是查索引函数**：索引函数感知不到 `ddres` 填 H 之前的跳过条件（参考星、`sysMap` 分组、`validobs` 失败、频率无效），会纳入全零列导致法方程奇异
3. **用完整 `R⁻¹` 而非 `diag(R)⁻¹`**：`ddcov` 产生的 R 不是对角阵（同一组双差共享参考星），对角近似会低估观测信息量、使 `Q_pos` 系统性偏大

**开关与回退**：`PrcOpt.diagMask & PrcOpt.DIAG_QPOS`（位值 32）打开才计算 `qPos`，默认关闭、零开销。计算点在 `ddres` 之后、`applyIggiii` 之前——此时 `H` 与 `R` 是同一次 `ddcov` 的产物、严格对齐；IGGIII 改写后的 `R` 块结构已被破坏，不能用于法方程。每次迭代覆写，最终取**最后一次迭代**的结果，且仅在 `stat != SOLQ_NONE` 时写入 `Sol.qPos`（`SOLQ_FIX` 走 FIX 分支，其余含 `SOLQ_FLOAT`/`SOLQ_SINGLE`/`SOLQ_DGPS` 走 FLOAT 分支）。`SolData.buildCovEcef` 的优先级是 `qPos`（长度恰为 9）→ `qr`；`qr[0]==0` 哨兵时 `covEcef` 为 `null`。

**对 adjust 的影响**：

- `CovAssembler.extractCovariance3x3` 读 `SolData.covEcef`，因此自动跟随该数据源切换，无需改 adjust 代码
- `Accuracy` 中的 `c12/c23/c31` **始终**读 `Sol.qr`，不随开关变化——这是刻意设计：显示口径与后处理口径分离
- 实测（BDS 双频，2 基站，215 个 FIX 历元）：

| 指标 | Pa（`qr`） | Q_pos |
|---|---|---|
| ENU σ 中位 | (12.57, 11.38, 34.60) mm | (12.00, 11.12, 31.31) mm |
| 三轴和比值中位 | — | 1.0000（偏小 88 / 相当 127 / 偏大 0） |
| FLOAT 历元三轴和比值中位 | — | 8.23（区间 1.08 ~ 80.04，样本 22） |

**结论**：FIX 历元下两者几乎等价（中位比值 1.0000，且从不偏大），`Q_pos` 略保守；FLOAT 历元下 `Q_pos` 显著偏大（中位 8.2 倍），因为单历元信息量远小于滤波累积信息——这正是"切断跨历元相关性污染"的预期表现，对 FLOAT 补位场景反而更诚实。开关**只改协方差，不改解算坐标与历元数**（回归测试逐历元比对确认位置完全一致）。

## 4. 信息流

```
基站A ──→ rtkpos() ──→ (x̂_A, C_A, P_rover_A) ─┐
基站B ──→ rtkpos() ──→ (x̂_B, C_B, P_rover_B) ─┤──→ 准入筛选 ──→ 间接平差(l, H, R) ──→ x̂_fused
基站C ──→ rtkpos() ──→ (x̂_C, C_C, P_rover_C) ─┘        │
                                                       └──→ 被拒 FLOAT → rejectedFloats（上报，不入 WLS）
```

每条基线在rtklib-core中独立完成完整的RTK解算（观测方程→Kalman滤波→模糊度固定），三条链路互不知情，只在最后一步汇合进入间接平差。

**准入筛选**（`selectAdmitted`）在平差之前决定哪些解进入 WLS：默认只放行 FIX；开启 `allowFloat` 后按 §2.5 的规则补位。FIX 与 FLOAT 的区分只发生在这一层，平差本身对两者一视同仁（FLOAT 已通过 R 膨胀降权）。

## 5. 理论局限性

### 5.1 核心问题：观测压缩的信息损失

RTK 的 Kalman 滤波器将原始观测值压缩为位置+协方差，该过程不可逆。原始观测中的卫星几何、大气延迟、多路径等结构化信息在输出中只体现为一个 3×3 协方差矩阵。adjust 在结果空间无论怎么构造 R 矩阵，都无法恢复这些结构化信息——这是"观测→位置"压缩的损失，不是 WLS 融合的损失（WLS 本身是统计最优的）。

### 5.2 Pr_fused ≠ 真实互协方差

第i条基线的RTK解可分解为：

```
l_i = x_true + δ_rover + δ_atm_i + δ_base_i + ε_i
```

| 误差项 | 含义 | 跨基线相关性 |
|--------|------|-------------|
| δ_rover | Rover端误差（多路径、接收机噪声） | 完全相关（同一接收机） |
| δ_atm_i | 第i条基线的大气残差 | 部分相关（基站距离近时） |
| δ_base_i | 基站端误差 | 不相关 |
| ε_i | 观测噪声 | 不相关 |

真实互协方差：

```
Cov(l_i, l_j) = P_rover_common + P_atm_corr(i,j)
```

当前实现**默认 `rho=0`（块对角 R）**，不使用 Pr_fused 作为非对角块。仅当显式设置 `rho>0` 时，才按 `R_ij = rho·sqrt(C_ii ⊙ C_jj)` 构造近似互协方差，此时存在以下偏差：

1. **量级偏差**：Pr_fused 是信息融合结果，量级偏小（Pr_fused ≤ min(P_rover_k)）；而真实互协方差与 C_ii 同量级
2. **Rover误差主导时偏差最严重**：短基线场景下Rover误差占比高，Pr_fused严重低估互协方差，R矩阵接近块对角，退化为简单加权平均
3. **Rover误差占比小时可能高估**：长基线场景下Pr_fused可能大于真实互协方差，制造虚假相关性

### 5.3 对定位精度的影响

**极小（<1%，短基线）**。原因：

```
σ_single = √(σ_common² + σ_independent²)        单基线
σ_fused  = √(σ_common² + σ_independent²/k)      k基线融合
```

短基线中 σ_common >> σ_independent（Rover多路径主导），融合对独立误差分量的缩减几乎不影响总精度。

### 5.4 对精度评定的影响

**显著（偏差可达±20%）**。Dx 和 σ₀ 直接依赖 R 矩阵，R 的偏差会传递到精度评定结果。

- 默认 `rho=0`（块对角 R）：忽略了 Rover 端公共误差的相关性，可能高估融合精度（σ₀ 偏大、Dx 偏小）
- `rho>0` 时：若 rho 取值不当，可能比完全忽略相关性更差——制造比实际更大或更小的虚假相关性

### 5.5 与观测层联合解算的真实差距

**重要修正**：在线性高斯系统下，序贯最小二乘 = 批量最小二乘。如果各基线误差确实独立且协方差准确，坐标层面的协方差融合就是观测层联合解的等价形式。

联合解真正的增量只有两处：

| 增量 | 说明 | 量级 |
|------|------|------|
| 更诚实的协方差 | 联合解正确建模跨基线相关性，不把公共误差当独立 | 精度评定改善，坐标改善小 |
| FLOAT→FIX加速 | k条基线观测同时约束Rover，等价观测数翻k倍，模糊度方差下降更快 | **可能显著**（需实验验证） |

注意：Rover端周跳在所有基线上是同历元共模的，多基线消不掉Rover自己的周跳。联合解的天花板仍然是Rover端公共误差。

## 6. 适用场景评估

| 场景 | 基线长度 | Rover误差占比 | 本模块效果 | 说明 |
|------|----------|--------------|-----------|------|
| 短基线网络RTK | <5km | 高 | 定位好，精度评定偏乐观 | Pr_fused低估互协方差，R接近块对角 |
| 中基线 | 5~15km | 中等 | 定位好，精度评定可接受 | Pr_fused偏差中等 |
| 长基线 | >15km | 低 | 定位好，精度评定可接受 | 独立性假设近似成立 |

**核心结论**：本模块对定位精度可靠，对精度评定需注意偏差方向。在监测应用中设置预警阈值时应留适当余量。

## 7. 不做的事

本模块明确**不**处理以下问题：

1. **观测层联合解算**：不修改rtklib-core的Kalman滤波器，不在观测空间做多基线联合约束（该能力由独立模块 `rtklib-joint` 以自己的 MBS 引擎实现，与本模块无接口关系，见 §1.2）
2. **模糊度联合固定**：各基线模糊度独立固定，不做跨基线PAR
3. **大气误差跨基线建模**：不估计基线间大气残差的互协方差
4. **Rover公共误差精确分离**：P_rover_common在结果空间不可观测，不引入经验参数估计

## 8. 观测层联合解算可行性评估

### 8.1 当前架构硬约束

单基线模型从数据层到模糊度固定全链路耦合：

| 层级 | 硬编码点 | 具体表现 |
|------|---------|---------|
| 数据层 | `Obsd.rcv` | 只有1（流动站）和2（基准站） |
| 状态向量 | `Rtk.rb[3]` | 单个基站坐标 |
| 状态向量 | `Rtk.x[nx]` | 一组基线向量+一组模糊度 |
| 观测方程 | `zdres(base=0/1)` | 流动站/基准站各调一次 |
| 双差 | `ddres()` | 单基线双差构造 |
| 模糊度 | `ddidx()` | 单基线双差索引 |

### 8.2 状态向量扩展

多基线联合状态向量：

```
x = [基线向量(3), 速度(3), 加速度(3), 电离层(MAXSAT), 对流层(6), GLO偏差(2),
     模糊度_A(MAXSAT*NF), 模糊度_B(MAXSAT*NF), 模糊度_C(MAXSAT*NF)]
    ← NR项（共用1组） →                                               ← k*NB项 →
```

**关键设计决策**：电离层/对流层状态**共用1组**，不复制k组。原因：这些大气状态的本质是rover→卫星视线方向的残余延迟，同一条视线对所有基线是同一个物理量（只是双差表达不同）。复制k组会引入虚假参数、恶化可观测性。

### 8.3 两步模糊度固定（降维路线）

90维MLAMBDA搜索是最大风险，但可以绕开：

```
第一步：每条基线独立LAMBDA（20~30维，现有逻辑不变）
        → 各自固定，标记固定质量（ratio、次优差）

第二步：把已固定基线当作强约束（坐标+小协方差）参与联合滤波
        → 联合滤波里待估模糊度只剩未固定的子集
```

这不是妥协，是工业界网络解算的标准做法（先固定强基线、再联合弱基线）。它把"90维LAMBDA + PAR研究课题"降级为"沿用现有PAR逻辑"。

### 8.4 风险评估

| 风险 | 严重程度 | 说明 |
|------|---------|------|
| **无参考实现可对比** | 🔴 高 | 单基线靠和C版逐历元对拍才验明白，多基线联合没有"标准答案" |
| LAMBDA搜索爆炸 | 🟡 中 | 两步固定路线可绕开，降为🟡 |
| 数值稳定性 | 🟡 中 | 有现成缓解手段（稀疏/块结构、UD分解、模糊度边缘化），是工程量问题不是可行性拦路虎 |
| 参考星选择 | 🟡 中 | 不同基站可能需不同参考星 |
| 历元对齐 | 🟡 中 | k个基站观测时间需插值对齐 |
| 7项优化兼容 | 🟡 中 | 需逐一适配 |

### 8.5 前置条件：收益量化

**动笔前必须先回答：联合解比坐标融合好多少？**

便宜的验证方法：拿实测多基线数据，离线分别跑：
- (a) 坐标融合（rtklib-adjust）
- (b) 批处理联合最小二乘（静态批量解，不需要实时滤波）

如果 (b) 相对 (a) 的提升 < 可感知阈值（固定率提升<10%、坐标RMS改善<20%），方案二直接否决。

这一步2~3天就能做完，应在任何代码之前。

### 8.6 决策建议

| 路径 | 适用条件 |
|------|---------|
| 维持rtklib-adjust | 目标是减少跳变、提升稳健性——已够用，把精力花在σ₀监控和Baarda迭代剔除策略上 |
| 先做离线对比实验（2~3天） | 任何情况下都该先做，量化联合解的真实增量 |
| 若实验显示收益显著 | 用两步固定版本立项，工期~2周且风险可控 |
| 基线很长、单基线固定困难 | 直接用服务端网络RTK/VRS——成熟方案，rtklib-java眼里仍然只是一个"基站" |

## 9. 基站异常诊断

### 9.1 问题背景

多基线平差中σ₀持续超限（σ₀>>1）表明基线间存在系统性不一致。在RTK场景下，最常见且影响最大的原因是**基站天线坐标错误**。

基站坐标误差δ_base会直接传递到Rover绝对坐标：

```
Rover绝对坐标 = 基站坐标(含误差δ_base) + 基线向量(精确)
```

但对**位移/变形监测**，基站坐标误差是常数，历元间差分时消除：

```
位移(t2-t1) = 基线(t2) - 基线(t1)  ← δ_base抵消
```

因此，基站坐标误差**不影响位移精度**，但影响绝对坐标和σ₀检验。

### 9.2 残差定位异常基站的理论

假设只有基站A坐标有偏差δ，其余基站正确，等权简化：

```
平差位置 x̂ = 真实位置 + δ/N

残差:
  v_A = x̂ - rover_A = -(N-1)δ/N    ← 异常基线
  v_i = x̂ - rover_i = +δ/N          ← 正常基线 (i≠A)
```

关键关系：**|v_A| = (N-1) × |v_i|**

| 基线数 | 残差关系 | 能否定位异常基站 |
|--------|---------|----------------|
| k=1 | df=0，无残差 | ❌ 不能 |
| k=2 | \|v_A\| = \|v_B\| | ❌ 残差等大，无法区分 |
| k=3 | \|v_A\| = 2\|v_B\| = 2\|v_C\| | ✅ 异常基线残差是正常的2倍 |
| k≥N | \|v_A\| = (N-1)\|v_i\| | ✅ N越大区分越明显 |

**k=2时必须借助额外信息（SPP定位）辅助判断方向。**

### 9.3 诊断流程

```
Step 1: 各基线RTK解算 → N组SolData
Step 2: 多基线平差 → σ₀, 残差v
Step 3: σ₀持续超限？
         ├─ 否 → 正常
         └─ 是 → Step 4: 定位异常基站
                   ├─ k=1: 无法诊断
                   ├─ k=2: SPP各基站，偏差最大的为异常
                   └─ k≥3: 残差分析，残差最大的为异常
Step 5: 以正常基站为参考，静态解算异常基站精确坐标
Step 6: 回调推送 BaseStationDiagnosis
```

### 9.4 触发机制：滑动窗口 + 超限比例

基站坐标错误是系统性偏差，每个历元都受影响。判断依据是σ₀**持续**超限，而非偶尔超限。

```
滑动窗口：最近100个历元
触发条件：窗口内 ≥80% 历元 σ₀ > 阈值
深度诊断：数据量 ≥2小时 后执行静态解算
```

偶然异常（多路径、周跳）只影响个别历元，不会触发深度诊断。

### 9.5 缓存策略

诊断结果缓存后不再重复计算和推送：

- 已诊断基站 → 跳过，不重复推送
- 调用方修正坐标后 → `clearDiagnosis(baseId)` 清除缓存，后续可重新验证
- 同一组基站只需诊断一次（基站坐标不会频繁变化）

### 9.6 静态解算的精度与局限

静态基线解算精度mm级，但给出的是**相对精确坐标**：

```
基站A建议坐标 = 基站B坐标(可能有误差) + 精确基线增量(mm级)
```

绝对精度取决于参考站（基站B）的真值。如果两个基站坐标都不确定，需要：
- 已知控制点坐标（最可靠）
- PPP精密单点定位（dm级，需精密星历）
- 长时间SPP（m级，仅辅助判断）

### 9.7 σ₀阈值选择

σ₀的理论分布：df × σ₀² ~ χ²(df)

| 基线数k | df | α=0.05临界值 | 工程阈值 |
|---------|-----|-------------|---------|
| 2 | 3 | 1.61 | 3.0 |
| 3 | 6 | 1.45 | 3.0 |
| 4 | 9 | 1.37 | 3.0 |

工程阈值3.0远大于统计临界值，因为实际中σ₀略超1.6很常见（协方差模型近似误差），不代表基站坐标问题。σ₀>10通常表示基线间明显不一致，σ₀>100表示基站坐标严重错误。

### 9.8 数据源抽象

`GnssDataSource` 接口统一了RTCM文件、RINEX文件、内存RTCM三种数据格式，诊断器只依赖此接口，不关心数据来源：

```
GnssDataSource (接口)
  ├── RtcmFileDataSource      事后RTCM文件
  ├── RinexFileDataSource     事后RINEX文件
  └── RtcmMemoryDataSource    实时RTCM流
```

### 9.9 与位移监测的关系

对于位移/变形监测应用，基站坐标误差**不影响位移精度**（常数偏差在历元差分中消除）。多基线平差的核心价值是：

1. **冗余观测** — 一条基线失效，另一条仍可用
2. **异常检测** — σ₀检验发现基线间不一致
3. **平滑效果** — 加权平均减小随机噪声

基站诊断功能的价值在于：当σ₀检验发现异常时，自动定位原因并给出修正建议，减少人工排查成本。

## 11. 结构化信息提取与平差优化（P0~P4）

### 11.1 问题背景

RTK解算内部拥有丰富的结构化信息（逐卫星残差、模糊度、H矩阵等），但传递到SolData时几乎全部被压缩为"位置+3×3协方差"。rtklib-adjust在结果空间融合时，无法利用这些信息做更精确的互协方差建模和基线质量评估。

### 11.2 优化层次总览

| 层次 | 名称 | 修改范围 | 核心收益 | 状态 |
|------|------|---------|---------|------|
| P0 | 基线质量加权 | 仅adjust | σ₀更稳健，假固定污染↓ | ✅ 已实现 |
| P1 | 逐卫星残差提取 | core(小)+adjust | σ₀精度评定偏差±20%→±10% | ✅ 已实现 |
| P2 | 基于残差的互协方差建模 | 仅adjust | 短基线互协方差更诚实 | 暂不实现（收益有限，P0+P1+P3已覆盖主要场景） |
| P3 | H矩阵位置分量提取 | core(中)+adjust | 非对称卫星几何场景改善 | ✅ 已实现 |
| P4 | 单历元归约协方差 `Q_pos` | core(中)+adjust(零改动) | 切断跨历元相关性，FLOAT 协方差更诚实 | ✅ 已实现（`DIAG_QPOS`，详见 §3.4） |

### 11.3 P0：基线质量加权

**原理**：FIX解本身有质量差异（ratio、numSat、age、DOP），这些指标反映协方差模型未捕获的额外不确定性。

**实现**：`BaselineEntry.qualityFactor`（0.01~1.0），通过缩放R矩阵对角块实现降权：

```
R_effective_ii = C_ii / w_i    （w_i = qualityFactor_i）
```

**质量因子计算**（`BaselineEntry.computeQualityFactor`）：

| 指标 | 阈值 | 降权方式 | 物理含义 |
|------|------|---------|---------|
| ratio < 3.0 | 3.0 | w *= ratio/3.0 | 低ratio FIX可能假固定 |
| numSat < 6 | 6 | w *= numSat/6.0 | 卫星数少→几何弱 |
| age > 5.0s | 5.0 | w *= 5.0/age | 差分龄期大→时效差 |
| hdop > 3.0 | 3.0 | w *= 3.0/hdop | HDOP大→水平几何差 |

**向后兼容**：`GnssBaselineAdjust.adjust(epoch)` 默认不启用质量加权（qualityWeight=false），与修改前行为一致。

### 11.4 P1：逐卫星诊断数据提取

**原理**：同一颗卫星在两条基线上的载波残差，Rover端分量完全相同（同一接收机、同一信号路径）。提取残差后可做跨基线相关性分析。

**实现**：扩展 `SatObsData`，新增8个诊断字段，由 `PrcOpt.diagMask` 位掩码控制：

| 掩码 | 常量 | 提取字段 | 来源(Ssat) |
|------|------|---------|-----------|
| 1 | `DIAG_SAT_RESIDUAL` | resp, resc | ssat.resp[0], ssat.resc[0] |
| 2 | `DIAG_SAT_AMBIGUITY` | amb, stdA | ssat.amb[0], ssat.stdA[0] |
| 4 | `DIAG_SAT_CYCLESLIP` | slip, gf, mw, rejc | ssat.slip[0], ssat.gf[0], ssat.mw[0], ssat.rejc[0] |

**内存增量**：每卫星+53B，12颗卫星+636B/历元/基线。9小时1Hz 3基线约+59MB（+40%）。

**向后兼容**：diagMask=0（默认）时，诊断字段为NaN/0，与修改前完全一致。

### 11.5 P3：H矩阵位置分量等效设计矩阵

**原理**：当前设计矩阵 H = [I₃; I₃; I₃] 假设各基线对Rover坐标的灵敏度相同。实际上不同基线的卫星几何、权重、模糊度固定状态不同，灵敏度也不同。

**实现**：从relpos()中提取H[:,0:3]和R，计算等效设计矩阵：

```
H_pos = H[:, 0:3]                    （nv×3位置分量子矩阵）
W = diag(R)^{-1}                     （对角加权）
N = H_pos^T × W × H_pos             （3×3法方程）
hPos = N^{-1} × H_pos^T × W         （3×3等效设计矩阵）
```

存入 `Sol.hPos[9]`（行优先），`CovAssembler.assembleDesignMatrix(epoch)` 使用hPos替代I₃。

**内存增量**：每历元每基线+73B（hPos）+20B（新息摘要）=+93B。9小时1Hz 3基线约+9MB。

**向后兼容**：hPos=null时退化为I₃，与修改前行为一致。

### 11.6 新息向量摘要

| 字段 | 计算公式 | 含义 |
|------|---------|------|
| `innovRms` | √(vᵀR⁻¹v / nv) | 新息RMS，模型拟合度指标 |
| `innovMax` | max(\|v_i\| / √R_ii) | 最大标准化新息，粗差检测指标 |
| `ddObsCount` | nv | 双差观测数，冗余度指标 |
