# rtklib-adjust 技术参考

## 1. 模块定位

本模块在**结果空间**对多条独立RTK基线做间接平差，属于"后验融合"类方法。

它**不是**观测层联合解算（统一Kalman滤波），不修改rtklib-core的解算流程。

### 1.1 核心价值

多基线融合解决的是**可靠性**问题，不是精度问题：

| 价值 | 优先级 | 本模块支持 |
|------|--------|-----------|
| FIX可用性提升 | ⭐⭐⭐⭐⭐ | ✅ 至少一条FIX就输出结果 |
| 假固定检测 | ⭐⭐⭐⭐ | ✅ σ₀检验 + Baarda T |
| 粗差基线剔除 | ⭐⭐⭐⭐ | ✅ Baarda数据探测 |
| 服务范围扩展 | ⭐⭐⭐ | ✅ 多基站覆盖 |
| 定位精度提升 | ⭐ | ✅ 但改善<1%（短基线） |

**定位精度改善<1%的原因**：各FIX解差异已在毫米级，残余误差主要是Rover端公共多路径——对公共误差取平均不会减小它。

## 2. 数学模型

### 2.1 观测方程

对同一历元 k 条独立FIX基线，各基线RTK解给出的Rover ECEF位置作为虚拟观测值：

```
l = H·x + v
```

| 符号 | 维度 | 含义 |
|------|------|------|
| l | 3k×1 | 观测向量，各基线给出的Rover位置 |
| H | 3k×3 | 设计矩阵，每3行为一个I₃ |
| x | 3×1 | 参数向量（Rover ECEF坐标） |
| v | 3k×1 | 残差向量 |

### 2.2 法方程与解

```
N = HᵀR⁻¹H          法方程系数矩阵
u = HᵀR⁻¹l          法方程常数项
dx = N⁻¹u            参数解
v = H·dx - l         残差
```

### 2.3 精度评定

```
df = 3k - 3                           自由度
σ₀² = vᵀR⁻¹v / df                    验后单位权方差 (df>0)
Dx = σ₀²·N⁻¹                          参数协方差 (df>0)，否则 Dx = N⁻¹
Qv = R - H·N⁻¹·Hᵀ                     残差协因数矩阵
T_i = |v_i| / (σ₀·√Qv_ii)             Baarda数据探测统计量
```

### 2.4 特殊情况

| k | df | 行为 |
|---|-----|------|
| 0 | - | 返回失败 |
| 1 | 0 | 无法精度评定，σ₀=NaN，不计算Baarda |
| ≥2 | 3(k-1) | 完整精度评定 |

## 3. 全局协方差矩阵 R 的构造

### 3.1 结构

```
k=1:  R = [C₁₁]                                    (3×3)

k=2:  R = [C₁₁,  Pr_fused]                         (6×6)
           [Pr_fused, C₂₂]

k=3:  R = [C₁₁,  Pr_fused, Pr_fused]               (9×9)
           [Pr_fused, C₂₂,  Pr_fused]
           [Pr_fused, Pr_fused, C₃₃]
```

- **对角块 C_ii**：第i条基线的自身协方差（3×3），来自RTK输出
- **非对角块 Pr_fused**：跨基线互协方差的近似值

### 3.2 Pr_fused 的计算

信息矩阵融合：

```
Pr_fused = (P_rover_1⁻¹ + P_rover_2⁻¹ + ... + P_rover_k⁻¹)⁻¹
```

其中 P_rover_i 是第i条基线的Rover位置协方差。

### 3.3 Pr_fused 的理论含义

Pr_fused 是"如果各基线Rover位置估计相互独立，加权融合后的最优估计协方差"。

**注意：这不是两条基线Rover位置估计之间的真实互协方差。** 真实互协方差应为Rover端公共误差的协方差，两者是不同的数学对象。详见第5节。

## 4. 信息流

```
基站A ──→ rtkpos() ──→ (x̂_A, C_A, P_rover_A) ─┐
基站B ──→ rtkpos() ──→ (x̂_B, C_B, P_rover_B) ─┤──→ 间接平差(l, H, R) ──→ x̂_fused
基站C ──→ rtkpos() ──→ (x̂_C, C_C, P_rover_C) ─┘
```

每条基线在rtklib-core中独立完成完整的RTK解算（观测方程→Kalman滤波→模糊度固定），三条链路互不知情，只在最后一步汇合进入间接平差。

## 5. 理论局限性

### 5.1 核心问题：结果空间融合的信息损失

RTK的Kalman滤波器将原始观测值压缩为位置+协方差，该过程不可逆。原始观测中的卫星几何、大气延迟、多路径等结构化信息在输出中只体现为一个3×3协方差矩阵。在结果空间无论怎么构造R矩阵，都无法恢复这些信息。

### 5.2 Pr_fused ≠ 真实互协方差

第i条基线的RTK解可分解为：

```
l_i = x_true + δ_rover + δ_atm_i + δ_base_i + ε_i
```

| 误差项 | 含义 | 跨基线相关性 |
|--------|------|-------------|
| δ_rover | Rover端误差（多路径、接收机噪声） | 完全相关（同一接收机） |
| δ_atm_i | 第i条基线的大气残差 | 部分相关（基站距离近时） |
| δ_base_i | 基站端误差 | 不相关 |
| ε_i | 观测噪声 | 不相关 |

真实互协方差：

```
Cov(l_i, l_j) = P_rover_common + P_atm_corr(i,j)
```

当前实现用 Pr_fused 替代上式右侧，存在以下偏差：

1. **量级偏差**：Pr_fused 是信息融合结果，量级偏小（Pr_fused ≤ min(P_rover_k)）；而真实互协方差与 C_ii 同量级
2. **Rover误差主导时偏差最严重**：短基线场景下Rover误差占比高，Pr_fused严重低估互协方差，R矩阵接近块对角，退化为简单加权平均
3. **Rover误差占比小时可能高估**：长基线场景下Pr_fused可能大于真实互协方差，制造虚假相关性

### 5.3 对定位精度的影响

**极小（<1%，短基线）**。原因：

```
σ_single = √(σ_common² + σ_independent²)        单基线
σ_fused  = √(σ_common² + σ_independent²/k)      k基线融合
```

短基线中 σ_common >> σ_independent（Rover多路径主导），融合对独立误差分量的缩减几乎不影响总精度。

### 5.4 对精度评定的影响

**显著（偏差可达±20%）**。Dx和σ₀直接依赖R矩阵，R的偏差会传递到精度评定结果。在Rover误差占比低的场景下，当前Pr_fused方案甚至可能比完全忽略相关性（块对角R）更差——制造了比不存在还大的虚假相关性。

### 5.5 与观测层联合解算的真实差距

**重要修正**：在线性高斯系统下，序贯最小二乘 = 批量最小二乘。如果各基线误差确实独立且协方差准确，坐标层面的协方差融合就是观测层联合解的等价形式。

联合解真正的增量只有两处：

| 增量 | 说明 | 量级 |
|------|------|------|
| 更诚实的协方差 | 联合解正确建模跨基线相关性，不把公共误差当独立 | 精度评定改善，坐标改善小 |
| FLOAT→FIX加速 | k条基线观测同时约束Rover，等价观测数翻k倍，模糊度方差下降更快 | **可能显著**（需实验验证） |

注意：Rover端周跳在所有基线上是同历元共模的，多基线消不掉Rover自己的周跳。联合解的天花板仍然是Rover端公共误差。

## 6. 适用场景评估

| 场景 | 基线长度 | Rover误差占比 | 本模块效果 | 说明 |
|------|----------|--------------|-----------|------|
| 短基线网络RTK | <5km | 高 | 定位好，精度评定偏乐观 | Pr_fused低估互协方差，R接近块对角 |
| 中基线 | 5~15km | 中等 | 定位好，精度评定可接受 | Pr_fused偏差中等 |
| 长基线 | >15km | 低 | 定位好，精度评定可接受 | 独立性假设近似成立 |

**核心结论**：本模块对定位精度可靠，对精度评定需注意偏差方向。在监测应用中设置预警阈值时应留适当余量。

## 7. 不做的事

本模块明确**不**处理以下问题：

1. **观测层联合解算**：不修改rtklib-core的Kalman滤波器，不在观测空间做多基线联合约束
2. **模糊度联合固定**：各基线模糊度独立固定，不做跨基线PAR
3. **大气误差跨基线建模**：不估计基线间大气残差的互协方差
4. **Rover公共误差精确分离**：P_rover_common在结果空间不可观测，不引入经验参数估计

## 8. 观测层联合解算可行性评估

### 8.1 当前架构硬约束

单基线模型从数据层到模糊度固定全链路耦合：

| 层级 | 硬编码点 | 具体表现 |
|------|---------|---------|
| 数据层 | `Obsd.rcv` | 只有1（流动站）和2（基准站） |
| 状态向量 | `Rtk.rb[3]` | 单个基站坐标 |
| 状态向量 | `Rtk.x[nx]` | 一组基线向量+一组模糊度 |
| 观测方程 | `zdres(base=0/1)` | 流动站/基准站各调一次 |
| 双差 | `ddres()` | 单基线双差构造 |
| 模糊度 | `ddidx()` | 单基线双差索引 |

### 8.2 状态向量扩展

多基线联合状态向量：

```
x = [基线向量(3), 速度(3), 加速度(3), 电离层(MAXSAT), 对流层(6), GLO偏差(2),
     模糊度_A(MAXSAT*NF), 模糊度_B(MAXSAT*NF), 模糊度_C(MAXSAT*NF)]
    ← NR项（共用1组） →                                               ← k*NB项 →
```

**关键设计决策**：电离层/对流层状态**共用1组**，不复制k组。原因：这些大气状态的本质是rover→卫星视线方向的残余延迟，同一条视线对所有基线是同一个物理量（只是双差表达不同）。复制k组会引入虚假参数、恶化可观测性。

### 8.3 两步模糊度固定（降维路线）

90维MLAMBDA搜索是最大风险，但可以绕开：

```
第一步：每条基线独立LAMBDA（20~30维，现有逻辑不变）
        → 各自固定，标记固定质量（ratio、次优差）

第二步：把已固定基线当作强约束（坐标+小协方差）参与联合滤波
        → 联合滤波里待估模糊度只剩未固定的子集
```

这不是妥协，是工业界网络解算的标准做法（先固定强基线、再联合弱基线）。它把"90维LAMBDA + PAR研究课题"降级为"沿用现有PAR逻辑"。

### 8.4 风险评估

| 风险 | 严重程度 | 说明 |
|------|---------|------|
| **无参考实现可对比** | 🔴 高 | 单基线靠和C版逐历元对拍才验明白，多基线联合没有"标准答案" |
| LAMBDA搜索爆炸 | 🟡 中 | 两步固定路线可绕开，降为🟡 |
| 数值稳定性 | 🟡 中 | 有现成缓解手段（稀疏/块结构、UD分解、模糊度边缘化），是工程量问题不是可行性拦路虎 |
| 参考星选择 | 🟡 中 | 不同基站可能需不同参考星 |
| 历元对齐 | 🟡 中 | k个基站观测时间需插值对齐 |
| 7项优化兼容 | 🟡 中 | 需逐一适配 |

### 8.5 前置条件：收益量化

**动笔前必须先回答：联合解比坐标融合好多少？**

便宜的验证方法：拿实测多基线数据，离线分别跑：
- (a) 坐标融合（rtklib-adjust）
- (b) 批处理联合最小二乘（静态批量解，不需要实时滤波）

如果 (b) 相对 (a) 的提升 < 可感知阈值（固定率提升<10%、坐标RMS改善<20%），方案二直接否决。

这一步2~3天就能做完，应在任何代码之前。

### 8.6 决策建议

| 路径 | 适用条件 |
|------|---------|
| 维持rtklib-adjust | 目标是减少跳变、提升稳健性——已够用，把精力花在σ₀监控和Baarda迭代剔除策略上 |
| 先做离线对比实验（2~3天） | 任何情况下都该先做，量化联合解的真实增量 |
| 若实验显示收益显著 | 用两步固定版本立项，工期~2周且风险可控 |
| 基线很长、单基线固定困难 | 直接用服务端网络RTK/VRS——成熟方案，rtklib-java眼里仍然只是一个"基站" |

## 9. 基站异常诊断

### 9.1 问题背景

多基线平差中σ₀持续超限（σ₀>>1）表明基线间存在系统性不一致。在RTK场景下，最常见且影响最大的原因是**基站天线坐标错误**。

基站坐标误差δ_base会直接传递到Rover绝对坐标：

```
Rover绝对坐标 = 基站坐标(含误差δ_base) + 基线向量(精确)
```

但对**位移/变形监测**，基站坐标误差是常数，历元间差分时消除：

```
位移(t2-t1) = 基线(t2) - 基线(t1)  ← δ_base抵消
```

因此，基站坐标误差**不影响位移精度**，但影响绝对坐标和σ₀检验。

### 9.2 残差定位异常基站的理论

假设只有基站A坐标有偏差δ，其余基站正确，等权简化：

```
平差位置 x̂ = 真实位置 + δ/N

残差:
  v_A = x̂ - rover_A = -(N-1)δ/N    ← 异常基线
  v_i = x̂ - rover_i = +δ/N          ← 正常基线 (i≠A)
```

关键关系：**|v_A| = (N-1) × |v_i|**

| 基线数 | 残差关系 | 能否定位异常基站 |
|--------|---------|----------------|
| k=1 | df=0，无残差 | ❌ 不能 |
| k=2 | \|v_A\| = \|v_B\| | ❌ 残差等大，无法区分 |
| k=3 | \|v_A\| = 2\|v_B\| = 2\|v_C\| | ✅ 异常基线残差是正常的2倍 |
| k≥N | \|v_A\| = (N-1)\|v_i\| | ✅ N越大区分越明显 |

**k=2时必须借助额外信息（SPP定位）辅助判断方向。**

### 9.3 诊断流程

```
Step 1: 各基线RTK解算 → N组SolData
Step 2: 多基线平差 → σ₀, 残差v
Step 3: σ₀持续超限？
         ├─ 否 → 正常
         └─ 是 → Step 4: 定位异常基站
                   ├─ k=1: 无法诊断
                   ├─ k=2: SPP各基站，偏差最大的为异常
                   └─ k≥3: 残差分析，残差最大的为异常
Step 5: 以正常基站为参考，静态解算异常基站精确坐标
Step 6: 回调推送 BaseStationDiagnosis
```

### 9.4 触发机制：滑动窗口 + 超限比例

基站坐标错误是系统性偏差，每个历元都受影响。判断依据是σ₀**持续**超限，而非偶尔超限。

```
滑动窗口：最近100个历元
触发条件：窗口内 ≥80% 历元 σ₀ > 阈值
深度诊断：数据量 ≥2小时 后执行静态解算
```

偶然异常（多路径、周跳）只影响个别历元，不会触发深度诊断。

### 9.5 缓存策略

诊断结果缓存后不再重复计算和推送：

- 已诊断基站 → 跳过，不重复推送
- 调用方修正坐标后 → `clearDiagnosis(baseId)` 清除缓存，后续可重新验证
- 同一组基站只需诊断一次（基站坐标不会频繁变化）

### 9.6 静态解算的精度与局限

静态基线解算精度mm级，但给出的是**相对精确坐标**：

```
基站A建议坐标 = 基站B坐标(可能有误差) + 精确基线增量(mm级)
```

绝对精度取决于参考站（基站B）的真值。如果两个基站坐标都不确定，需要：
- 已知控制点坐标（最可靠）
- PPP精密单点定位（dm级，需精密星历）
- 长时间SPP（m级，仅辅助判断）

### 9.7 σ₀阈值选择

σ₀的理论分布：df × σ₀² ~ χ²(df)

| 基线数k | df | α=0.05临界值 | 工程阈值 |
|---------|-----|-------------|---------|
| 2 | 3 | 1.61 | 3.0 |
| 3 | 6 | 1.45 | 3.0 |
| 4 | 9 | 1.37 | 3.0 |

工程阈值3.0远大于统计临界值，因为实际中σ₀略超1.6很常见（协方差模型近似误差），不代表基站坐标问题。σ₀>10通常表示基线间明显不一致，σ₀>100表示基站坐标严重错误。

### 9.8 数据源抽象

`GnssDataSource` 接口统一了RTCM文件、RINEX文件、内存RTCM三种数据格式，诊断器只依赖此接口，不关心数据来源：

```
GnssDataSource (接口)
  ├── RtcmFileDataSource      事后RTCM文件
  ├── RinexFileDataSource     事后RINEX文件
  └── RtcmMemoryDataSource    实时RTCM流
```

### 9.9 与位移监测的关系

对于位移/变形监测应用，基站坐标误差**不影响位移精度**（常数偏差在历元差分中消除）。多基线平差的核心价值是：

1. **冗余观测** — 一条基线失效，另一条仍可用
2. **异常检测** — σ₀检验发现基线间不一致
3. **平滑效果** — 加权平均减小随机噪声

基站诊断功能的价值在于：当σ₀检验发现异常时，自动定位原因并给出修正建议，减少人工排查成本。
