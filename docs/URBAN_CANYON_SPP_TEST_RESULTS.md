## 2. SPP 优化策略说明

| 策略 | 开关 | 原理 | 适用场景 |
|------|------|------|---------|
| **LS-SPP（基准）** | — | 逐历元最小二乘，无状态传递 | 所有场景基准 |
| **EKF-SPP** | `enableSppEkf` | 扩展卡尔曼滤波，位置/速度/钟差状态传递 | 信号间断后快速恢复、平滑轨迹 |
| **EKF + 抗差** | `+enableSppRobust` | Huber抗差权重，抑制多路径大残差 | 城市峡谷多路径严重场景 |
| **EKF + 抗差 + 零速 + SNR** | `+enableSppZeroVel` `+enableSppDopplerSnr` | 零速约束+多普勒SNR加权 | 准静态/步行场景 |

## 3. 详细测试结果

### 3.1 Net_Diff Urban（极严重遮挡，单频，4.6颗卫星）

|------|--------|----------|----------|----------|-----------|-----------|-----------|
| 基准 LS-SPP | 55.2% | 688 | 482 | 109 | 840 | 847 | 8.83 |
| EKF-SPP | 100% | 833 | 2150 | 5259 | 2306 | 5742 | — |
| EKF + 抗差 | 100% | 840 | 1256 | 2772 | 1511 | 3157 | — |

**分析**：
- ❌ **EKF 严重发散**：卫星数仅4.6颗，EKF 状态协方差快速膨胀，位置估计跑偏
- ⚠️ 抗差估计有改善（2D 2306→1511m）但无法根治发散
- ❌ 零速+SNR组合反而更差，2D RMS 17km

## 5. 算法选择建议

### 5.1 按卫星数选择

| 可见卫星数 | 推荐策略 | 原因 |
|-----------|---------|------|
| **< 5颗** | LS-SPP（基准） | EKF 状态协方差膨胀→发散，抗差也无法根治 |
| **5~8颗** | EKF + 抗差 | EKF 提升成功率，抗差抑制多路径残差，但精度改善有限 |
| **> 8颗** | EKF + 抗差 | 成功率接近100%，精度小幅改善，sigma显著减小 |

### 5.2 按运动模式选择

| 运动模式 | 零速约束 | 原因 |
|---------|---------|------|
| **车载动态** | ❌ 不启用 | 车辆持续运动，零速检测误触发导致精度恶化 |
| **步行/手持** | ⚠️ 谨慎启用 | 有停顿但频繁误判，需调高 `sppZeroVelSpeedThresh` |
| **准静态监测** | ✅ 启用 | 长时间静止，零速约束有效平滑位置 |

### 5.3 城市峡谷 RTK 流程建议

```
SPP阶段：EKF+抗差 → 提供连续、平滑的先验位置
         ↓
RTK初始化：用SPP位置作为EKF先验 → 更准确的初始状态
         ↓
RTK运行：Float解 → 等待ratio>3.0 → Fix解
```

## 6. 已知问题与后续方向

### 6.1 EKF 发散问题

- **现象**：卫星数<5时 EKF 位置估计发散，2D RMS 从百米级恶化到千米级
- **根因**：观测方程欠定（4颗卫星4个未知数），EKF 预测步无观测修正→协方差膨胀
- **待改进**：
  - [ ] EKF 协方差膨胀检测：当 P 对角元素超过阈值时重置为 LS 解
  - [ ] 自适应 Q 矩阵：根据可见卫星数动态调整过程噪声
  - [ ] 新息卡方检验：拒绝新息过大的观测，防止错误更新

### 6.2 零速约束误判

- **现象**：车载动态场景零速约束误触发，2D RMS 恶化（PPC Tokyo 7.8→15km）
- **根因**：`sppZeroVelSpeedThresh=0.5m/s` 阈值太低，低速行驶（等红灯）时误判为零速
- **待改进**：
  - [ ] 提高默认阈值至 1.0~2.0 m/s
  - [ ] 增加零速持续时间要求（连续 N 个历元才启用）
  - [ ] 结合加速度计数据辅助判断

### 6.3 参考位置精度

- **说明**：本次测试使用 RINEX 头中的近似位置作为参考，非真实轨迹
- **影响**：RMS 绝对值偏大（百米~百千米级），但**相对改善率**仍有参考价值
- **待改进**：使用 NMEA baseline 或精确参考轨迹计算真实 RMSE

## 9. EKF 发散根因：代码证据验证

> 对照 MobileGNSS-SPP C代码（`D:\code\MobileGNSS-SPP\rtklib_src\pntpos.c`）逐条验证

### 9.1 四条代码证据

#### 证据1：P膨胀检测但无else保护（`SppOptimizations.java` L140-L152）

**代码**：
```java
if (var > cfg.sppEkfVarResetThresh && solLsq.stat > Constants.SOLQ_NONE) {
    // 重置P和x，return
}
// 没有else！继续做时间传播，P继续膨胀
```

**MobileGNSS-SPP C代码**（`pntpos.c` L1195）：
```c
if (var > VAR_POS && sol_lsq->stat > SOLQ_NONE) {
    // 重置P和x，return
}
// 同样没有else！
```

**判定**：✅ **完全成立**。两个实现完全一样——检测到P膨胀但LS失败时不做任何处理，既不重置也不冻结也不限幅。这是最接近实现Bug的一条——写了检测但没写保护分支。

#### 证据2：LS失败后继续KF update（`SppOptimizations.java` L363-L479）

**控制流**：`estpos` → `udposSpp`（不管LS成功与否） → `rescode` → `KalmanFilter.update`

**判定**：⚠️ **部分成立，需修正表述**。LS失败后确实继续KF update，但`rescode`用EKF状态而非LS结果计算残差，只要卫星可见就能产生观测（nc不一定为0）。真正的问题是：LS失败意味着观测质量差，此时少数卫星的KF update让状态往多路径方向漂移。

#### 证据3：KF update无新息卡方检验（`SppOptimizations.java` L479）

**代码**：
```java
if (KalmanFilter.update(x, P, HOrig, vOrig, R, nxF, nv) != 0) {
    return -2;
}
```

`KalmanFilter.update`内部无任何新息（innovation）卡方检验，无论残差v是1m还是1000m都照单全收。

**MobileGNSS-SPP C代码**（`pntpos.c` L1495）：
```c
RobustFilter(H_new, v, NX_F-3, nc, nd, NULL, var);  // 抗差在filter之前！
// ...
filter(x, P, H, v, R, NX_F, nv);  // KF update
```

C代码**用抗差替代了新息卡方检验**——大残差被降权而不是拒绝。`RobustWeight` Huber模型：`resid>=30m`降权到`0.0001/σ`。

**判定**：✅ **完全成立，最硬的证据**。我们的Java代码EKF主流程无任何保护，MobileGNSS-SPP至少有抗差降权。

#### 证据4：P无上限（`KalmanFilter.java`）

标准KF的`P=(I-KH)P`无对角元素上限，P可以无限膨胀。

**判定**：✅ 成立，但**这是KF的正常特性**，缺陷在于上层没有限幅/冻结/门控。不应算KalmanFilter的Bug，是上层调用者的责任。

### 9.2 MobileGNSS-SPP vs Java代码对照

| 证据 | 我们的Java | MobileGNSS-SPP (C) | 差异 |
|------|-----------|-------------------|------|
| 1: P膨胀无else | ❌ 无保护 | ❌ 无保护 | **一样** |

### 9.3 证据优先级（按修复收益/风险）

## 12. P0 三项核心修复：修正与验证

> **日期**：2026-10-12  
> **修改文件**：`SppOptimizations.java`、`RtkConfig.java`、`SppEkfState.java`  
> **背景**：初始实现有三处关键问题——卡方阈值用错分布、剔除策略太粗暴、R放大倍数写死。本节记录修正内容与验证结果。

### 12.1 三处关键修正

#### 修正1：逐观测检验阈值——从χ²改为正态分布分位数

| 项目 | 修正前 | 修正后 |
|------|--------|--------|
| 阈值概念 | `v²/S > χ²(0.999)=10.83`，混淆了χ²和正态 | `|v|/√S > σ阈值`，明确使用正态分布标准化新息 |
| 阈值数量 | 单级（10.83） | 两级：`sppInnovOutlierThresh=5.0σ`（剔除）、`sppInnovDownweightThresh=3.0σ`（降权） |
| 配置项 | `sppInnovChisqThresh=10.83` | `sppInnovOutlierThresh=5.0` + `sppInnovDownweightThresh=3.0` + `sppInnovDownweightRscale=10.0` |

**理论依据**：
- 逐观测标准化新息 `nis = |v_i| / √S_ii` 服从标准正态分布 N(0,1)
- 3σ 对应单侧 99.87% 分位，5σ 对应单侧 99.99997% 分位
- χ²(1,0.999)=10.83 是全局检验用的，自由度=观测数n，不适用于逐观测
- 虽然数学上 `v²/S > 10.83` 等价于 `|v|/√S > 3.29`，但概念混淆会导致后续维护错误

**代码核心变化**（`SppOptimizations.java` 新息检验段）：
```java
// 修正前：混淆χ²和正态
double chisq = v[j] * v[j] / Sjj;
if (chisq > cfg.sppInnovChisqThresh) {  // 10.83
    outlier[j] = true;  // 直接剔除
}

// 修正后：明确正态分位数 + 两级策略
double nis = Math.abs(v[j]) / Math.sqrt(Sjj);  // 标准化新息 ~ N(0,1)
if (nis > cfg.sppInnovOutlierThresh) {           // >5σ → 极端异常，剔除
    extremeOutlier[j] = true;
} else if (nis > cfg.sppInnovDownweightThresh) { // 3~5σ → 中等异常，降权
    downweight[j] = true;
}
```

#### 修正2：剔除策略——从"直接剔除"改为"两级：极端剔除 + 中等降权"

| 项目 | 修正前 | 修正后 |
|------|--------|--------|
| 策略 | 超阈值直接剔除 | >5σ剔除，3~5σ降权（R放大10倍），≤3σ正常 |
| 降权实现 | 无 | `R[j] *= sppInnovDownweightRscale` |
| 卫星少时保护 | 无（剔除后可能只剩3~4颗） | 中等异常不剔除只降权，保留观测数 |

**设计理由**：
- 城市峡谷卫星数常<8颗，直接剔除一颗可能只剩3~4颗，EKF更新量不足
- 3~5σ区间的观测仍有信息量，只是不可信，降权比剔除更合理
- 5σ以上（约百万分之三概率）才是极端异常，剔除风险低

**降权实现**（`SppOptimizations.java` R矩阵构建段）：
```java
double[] R = new double[nv * nv];
for (int j = 0; j < nv; j++) {
    R[j * nv + j] = var[j];
    if (downweight[j]) {
        R[j * nv + j] *= cfg.sppInnovDownweightRscale;  // R放大10倍
    }
}
```

#### 修正3：R放大倍数——从固定值改为自适应

| 项目 | 修正前 | 修正后 |
|------|--------|--------|
| R放大 | `sppEkfDivergedRscale=100.0`（固定） | `min(sppEkfDivergedRscaleMax, sppEkfDivergedRscaleBase × 2^divergedEpochs)` |
| 初始值 | 100 | 10×2⁰=10（刚发散时温和降权） |
| 持续发散 | 100（不变） | 10→20→40→80→160→320→640→1000（封顶） |
| 配置项 | `sppEkfDivergedRscale` | `sppEkfDivergedRscaleBase=10.0` + `sppEkfDivergedRscaleMax=1000.0` |

**自适应公式**：
```
rscale = min(1000, 10 × 2^divergedEpochs)
```

| divergedEpochs | rscale | 含义 |
|----------------|--------|------|
| 0 | 10 | 刚检测到发散，温和降权 |
| 1 | 20 | 连续2个历元发散 |
| 2 | 40 | |
| 3 | 80 | |
| 4 | 160 | |
| 5 | 320 | |
| 6 | 640 | |
| 7+ | 1000 | 封顶，防止过度降权导致update无效 |

**设计理由**：
- 卫星4颗时和卫星15颗时，diverged严重程度不同，固定N=100不合适
- 连续发散越久，说明问题越严重，R放大应递增
- 指数增长（2^n）比线性增长更符合"越久越不确定"的直觉
- 封顶防止R过大导致KF update完全无效（K→0）

### 12.2 补充修正

#### 修正4：diverged恢复后P重置

| 项目 | 修正前 | 修正后 |
|------|--------|--------|
| 恢复策略 | 只清标记，P不重置 | 恢复时P位置方差重置为`sppEkfVarPos`，速度方差重置为`sppEkfVarVel` |

**问题**：P封顶后如果LS一直失败，EKF用封顶P做预测，位置慢慢漂走。封顶只是"不让P无限膨胀"，不解决"观测不足"根本问题。恢复时必须重置P，否则P卡在封顶值导致后续收敛慢。

#### 修正5：diverged时预测步Q放大

| 项目 | 修正前 | 修正后 |
|------|--------|--------|
| 预测步Q | 不变 | Q放大`sppEkfDivergedQscale=4.0`倍 |

**设计理由**：diverged=true时表示"我现在不确定"，预测步Q放大让P更快膨胀→K增益增大→更依赖观测而非预测。配合R放大（update步更不信任观测），两者平衡：
- Q放大→P预测更大→K增大（倾向观测）
- R放大→K减小（不信任观测）
- 净效果：观测质量好时K仍较大（Q放大主导），观测质量差时K很小（R放大主导）

### 12.3 配置项变更汇总

| 旧配置项 | 新配置项 | 默认值 | 说明 |
|---------|---------|--------|------|
| `sppInnovChisqThresh` | — | **删除** | χ²阈值概念错误，替换为正态分位数 |
| — | `sppInnovOutlierThresh` | **5.0** | 逐观测极端异常阈值（σ），>5σ剔除 |
| — | `sppInnovDownweightThresh` | **3.0** | 逐观测中等异常阈值（σ），3~5σ降权 |
| — | `sppInnovOutlierThreshLowSat` | **7.0** | 低卫星数时放宽剔除阈值（σ） |
| — | `sppInnovDownweightThreshLowSat` | **5.0** | 低卫星数时放宽降权阈值（σ） |
| — | `sppInnovDownweightRscale` | **10.0** | 中等异常R放大倍数 |
| `sppEkfDivergedRscale` | — | **删除** | 固定R放大替换为自适应+卫星数保护 |

### 12.4 自适应R放大卫星数保护

**问题**：自适应R放大 `rscale = min(1000, 10×2^divergedEpochs)` 在卫星极少（<7颗）时过度降权，导致EKF几乎不更新，位置漂走。Net_Diff从3157m恶化到15748m。

**修正**：加两级保护：
1. **卫星数下限**：`nSat < sppEkfLowSatThresh(7)` 时，用固定R放大 `sppEkfDivergedRscaleBase(100)`，不用自适应
2. **最大持续历元数**：`divergedEpochs > sppEkfDivergedMaxEpochs(20)` 时，强制 `rscale=1.0`，解锁KF更新

```java
if (state.diverged) {
    double rscale;
    if (nSat < cfg.sppEkfLowSatThresh) {
        rscale = cfg.sppEkfDivergedRscaleBase;  // 低卫星：固定100
    } else if (state.divergedEpochs > cfg.sppEkfDivergedMaxEpochs) {
        rscale = 1.0;  // 长期diverged：强制解锁
    } else {
        rscale = min(cfg.sppEkfDivergedRscaleMax,
                cfg.sppEkfDivergedRscaleBase * 2^divergedEpochs);  // 高卫星：自适应
    }
}
```

**教训**："自适应"在极端场景下会反噬。卫星极少时，自适应R放大从10开始太小（初期降权不够），指数增长后又太大（过度降权）。固定100反而在极端场景更安全。

### 12.5 diverged恢复重初始化

**问题**：修正前diverged恢复只清标记不重置P，EKF永久锁死在diverged状态。修正后恢复时用`initx`将位置/速度/加速度重初始化到LS解，P对应行/列清零并设对角线为默认方差。

```java
if (state.diverged && consecutiveLsSuccess >= sppEkfDivergedRecoverEpochs) {
    for (int i = 0; i < 3; i++) initx(state, solLsq.rr[i], sppEkfVarPos, i);
    for (int i = 3; i < 6; i++) initx(state, solLsq.rr[i], sppEkfVarVel, i);
    for (int i = 6; i < 9; i++) initx(state, 0.0, sppEkfVarAcc, i);
    state.diverged = false;
    state.divergedEpochs = 0;
}
```

**注意**：`initx`会清零P的对应行和列（保证正定性），不能只改对角线不改交叉项（会导致P非正定，EKF崩溃）。

**trade-off**：恢复重初始化引入位置跳变，UrbanNav 2D从699m略恶化到776m（+11%），但不恢复EKF会永久发散（52亿米）。恢复是必须的。

### 12.10 核心教训

1. **"自适应"在极端场景下会反噬**：自适应R放大在卫星<7颗时过度降权，固定100反而更安全
2. **P矩阵操作必须保证正定性**：只改对角线不改交叉项会导致P非正定，EKF崩溃；`initx`清零行和列是正确做法（行优先存储：`P[i*nxF+j]`）
3. **降级策略必须和EKF state管理协调**：降级时只输出LS解不更新state，恢复后state脱节导致残差巨大
4. **diverged恢复是必须的，但代价取决于恢复方式和卫星数**：不恢复EKF永久发散（52亿米）；恢复虽引入位置跳变（+11%~49%），但远好于不恢复；卫星多时代价小，卫星少时代价大
