## 1. 核心结论

1. **架构可行性已验证**：「外挂式 AI 辅助（SPI 注入 + 默认关闭 + 失败退化）」是当前 GNSS 确定性解算链中唯一安全的接入模式。未注入 `AiProvider` 时保持 I-1 零回归不变式，core 行为与 v3.4.0 逐位一致。

2. **AI 的真实价值已可量化**（本轮首次以**双跑配对**而非离线代理给出）：
   - 测试站（2 个完全未见站，45,501 历元）：固定率 **23.47% → 25.33%（+1.85 pp）**，错误固定率 **14.58% → 13.18%**，水平 RMS **152.1 → 139.9 cm**，垂直 RMS **383.3 → 319.8 cm**。
   - 全 6 站（135,198 历元）：固定率 **+2.01 pp**，错误固定率 **13.65% → 12.67%**，水平 RMS **170.3 → 147.9 cm（−13.2%）**，垂直 RMS **319.9 → 266.1 cm（−16.8%）**。

3. **A3「真的在起作用」已用真实配对证实**：测试站 G0（`|before| ≥ 3σ_dd`）命中 20,780 行，其中 **10,386 行（50.0%）**构成有效改正、覆盖 **33 颗卫星**。零基线自检（A 组，未注入）`max|after−before|` **恒为 0.000 m**（非零行 0/1,051,993），证明配对索引与取数无错位。

4. **训练范式的陷阱已闭环**：单侧监督对标签的物理口径要求极度严苛。双差（DD）标签与单星（SD）施加口径不匹配，会让模型学到**反向**偏差量，产生「越改越差但离线指标虚高」的假象。修正为 `label = median_{(epoch,frq)}(before) − before` 后重训，离线残差改善由负转正（**12.68%**，95% CI [12.52%, 12.81%]），真实配对亦同步转正。

5. **收益主要来自 `varianceScale` 头，`biasMeters` 头为边际贡献**：D 组（强制 `biasMeters≡0`）在固定率、错误固定率、位置 RMS 上与 C 组（双头全开）几乎并列，部分指标（垂直 RMS、绝对错误固定数）甚至略优。该结论对后续是否保留偏差头具有直接决策价值（§4.4）。

6. **方案 B（端到端坐标 Loss）已执行完毕：不交付，但作为「有效但不可控」的实验 provider 保留**：两轮迭代（v1 裸 3 维归一化 + `scale_max=4.0`、v2 的 H/V 各自按 L0 归一化 + `scale_max=3.0`）在**同一套 Java 双跑配对**上均未实现整体 135,198 历元的 H/V 双赢——v2 的 D 组为 H **149.0 cm** / V **300.8 cm**，相对生产 D 组（146.2 / 265.6）**两项同时变差**（+2.8 cm / +35.2 cm）。按预先约定的判据**立即停止调参**。但客观评估（§8.9）显示它相对「完全不注入」在所有指标上更好（3D 362.4 → 311.6 cm，−14.0%），且 e2e-v1 的水平 RMS **140.0 cm 为全部 7 组最低**；否决理由是**不稳定**（目标函数重加权即摆动 7.4%~17.3%）与**离线指标/真实指标符号相反**，而非「无效」。故处置为**默认关闭、仅显式注入的实验 provider**，最终交付仍为方案 A。

7. **激进钳位边界探索（§8.10）不改变第 6 条的处置**：三组配置（A 激进 / B 保守 / B 激进）在测试站 2 站 × 4 日共 192 run 上给出「A 激进为空操作」「B 激进三项全正（假固定 −17%、正确固定不丢、精度 −2.3%）」「A 与 B 是交换而非强弱（A 赢可用性约 3%，B 赢精度 5%~7%）」。但该口径只统计水平 H，真值与聚合方式均不同于 §8.4，且所有配对 t 值 ≤ 1.7、无一项达 0.05 显著，因此**仅作方案 B 能力边界证据**，不构成交付判定（见 §8.10.7 与附录 B 第 8 条）。

## 2. 架构设计说明

| 项 | 实现 |
|---|---|
| 注入点 | `AiProvider` + `AiHooks`，单例 ThreadLocal 隔离；接口一与接口三为**两个独立方法**，各自可返回 `null` |
| 默认状态 | **无注入即关闭**。不注入时 core 不调用任何 AI 代码路径（I-1） |
| 施加位置 | [RtkCore.java:2088](file:///D:/code/rtklib_java/rtklib-core/src/main/java/org/rtklib/java/rtkpos/RtkCore.java#L2088)：`v[nv] -= aiBias[refIdx*nf+frq] - aiBias[j*nf+frq]`（双差内成对扣除，参考星项同时进入） |
| 输出钳位 | [RtkCore.java:1827-1852](file:///D:/code/rtklib_java/rtklib-core/src/main/java/org/rtklib/java/rtkpos/RtkCore.java#L1827-L1852)：`varianceScale < 1.0` 强制置 1.0（单侧膨胀）；`|biasMeters| > obsCorrectorMaxBias`（默认 2.0 m）置 0（不钳边界） |
| 降级策略 | 输出非法（null / 长度不符 / 非有限）→ 本历元按**不干预**处理并写 `AI_DEGRADE` trace；实现抛异常同理（catch `Throwable`） |
| 幂等性 | `v[nv]` 每历元由 `y` 现场重算，`ddres` 多次调用不重复扣除偏差 |
| 热路径约束 | 每历元**批量推理一次**，`varerr` 只读查表，不在内层循环推理 |

**为什么单侧膨胀是硬约束**：接口三改观测值但不剔除观测，若不限制 `varianceScale ≥ 1.0`，模型可通过「压低方差 + 抬高偏差」制造过度自信，直接推高错误固定率——这是接口三唯一可能造成的实质伤害，故以契约级钳位（而非训练约束）拦住。

### 3.3 三组配对（A / C / D）

| 组 | 定义 | 用途 |
|---|---|---|

现场设备 RINEX 头坐标不可用（与实测固定解相差数十米），故参考坐标沿用 `fix_validator.assemble` 的自动真值：逐日稳健中心 + 跨日中位裁决（逐日偏离 > 0.10 m 的站日整体拒用）。**只用 A 组（未注入）的固定解估计**——用 C 组会把待评估的改正算进真值。本次 6 站全部 4 日通过跨日校验（逐日偏离 5~11 mm）。

**必须如实记录的三条风险**：

1. **2/6 站的错误固定率上升**（`…268595` +1.08 pp、`…860355` +0.81 pp），C 组与 D 组**同向**（说明由尺度头驱动，不是偏差头引入）。这两站同时是固定率增益最小的站之一（+0.73 pp / +2.21 pp），即「多固的那部分里错的比例高于基线」。
2. **全站绝对错误固定数在 C 组上升 35 个（+0.8%）**。`wrong_fix_rate` 的分母是固定历元，固定数增加 2,713 时该比例可以下降而绝对数上升。**但新增固定历元中的错误固定率仅 1.29%**（远低于 13.65% 的基线），说明「比例下降」不是分母稀释出来的假象，边际新增固定质量显著高于均值。
3. **`…156203`（早停站）错误固定率基数极高（48.66%）**，该站即便在 A 组也不具备可用性，其「下降 1.54 pp」不能作为有效性证据；A3 判定亦**严格排除**训练站与早停站（只用 2 个未见测试站）。

**A2 判定口径声明**：§7.5.2 的写法是「C 组 vs A 组」，故 A2 总判定取整体口径；逐站变差的分站**必须在报告中单独披露**（本表），不得用整体通过掩盖。若后续要求「任一站变差即整组不通过」，则 A2-2 应改为逐站口径——**这是判据口径变更，须走新决策记录**，不得事后追认。

## 8. 方案 B 端到端训练：执行记录与处置结论

> 本节是**已执行**的对照实验，不是计划。结论：**不交付**，但**保留为「有效但不可控」的实验 provider**（默认关闭、仅显式注入），交付方案 A（§6）。客观可用性依据见 §8.9。

### 8.1 目标与事先约定的判据

用「最终坐标与真值的误差」直接反传，绕开人造标签的物理口径约束（§5 失效 1 的根因），验证端到端范式能否超过现有标签监督（方案 A）。

**判据（执行前写定，不事后调整）**：在同一套 Java 双跑配对的**整体 135,198 历元**口径下，端到端模型的 **H RMS 与 V RMS 必须同时低于生产 D 组**（146.2 cm / 265.6 cm）。任一项不达标即**立即停止调参**（处置方式见 §8.6 / §8.9.6）。

### 8.2 实现（与方案 A 的唯一差异是 Loss）

架构**完全不变**：SPI 注入 + 默认关闭 + 失败退化；输入 17 维特征、输出 `[batch, 2]`（`biasMeters` / `varianceScale`），`tanh` / `sigmoid` 钳位与 Java 侧 core 逐位一致；导出 `obs_corrector_e2e.onnx` + `.norm.json`，**Java 侧零改动**，只换模型文件。

差异只在训练目标（[train_e2e.py](file:///D:/code/rtklib_java/rtklib-ai/training/obs_corrector/train_e2e.py)）：

- 用 [e2e_wls.py](file:///D:/code/rtklib_java/rtklib-ai/training/obs_corrector/e2e_wls.py) 的可导单步 WLS 把 `bias`/`scale` 一路算到坐标，**几何矩阵 `H` 做 `detach`**，梯度只回传给模型输出；
- 数据切分与方案 A 完全一致（两层：先按站、再在训练站内按天），`seed` 相同，保证指标可比；
- WLS 分组用整段 1 小时 run（压制单历元噪声，保留系统偏差）；
- 两个 L2 正则：`β` 锚定 `H` 零空间、`scale` 锚定方差整体缩放自由度（两者对坐标 Loss 无梯度，不加会自由漂移）。

**前置可行性已验证**：参考星、几何矩阵、方差、先验位置误差均可从现有采集目录无损复原，无需新增采集逻辑。参考系换算用**逐 run 代数一致性**校验（`WLS(before)−WLS(r)` 必须等于 `WLS(h·dx)`，WLS 线性保证），偏差 H/V 均 **< 0.01 mm**——先前用「残差均值降幅」判断会误报，因为残差主体是多路径/电离层投影，与位置误差无关。

### 8.3 两轮迭代（按判据逐步收紧，两轮均已跑完配对）

| 轮次 | Loss 归一化 | `scale_max` | 说明 |
|---|---|---|---|
| v1 | 裸 3 维平方和除以单一 `L0` | 4.0 | 垂直误差（~6.9 m）量级压过水平（~3.8 m），梯度被垂直项独占 |
| v2 | **H、V 各自按自己的 `L0` 归一化**（两项起点均为 1.0） | **3.0** | 让模型对水平/垂直同等负责，同时抑制对差站的过度降权 |

v2 训练（40 epoch，无早停）离线代理指标：val 坐标 Loss **3.9338 → 1.0758（−72.7%）**，其中 H 2.3384 → 0.6787、V 1.5954 → 0.3971；test **5.0235 → 1.1172（−77.8%）**。模型输出：`|bias|` 均值 1.06 m（p95 3.62 m），`scale` 均值 1.45（p05 1.06 / p95 2.66，贴地板 0.0%，未顶到 3.0 上界）。

> 注意：该离线指标是**DDRES 码残差的静态码解算代理**，与 Java 侧载波 RTK 的 H/V RMS 不同口径，**不能**跨口径比较；唯一有效判据是 §8.4 的同历元配对。

**未达标 ⇒ 不交付。** 判据要求 H 与 V 同时低于生产 D 组，v2 两项同时更差，因此按约定**立即停止，不再尝试任何调参**（含 epoch / `lambda` / 网络宽度 / 早停策略 / 数据集扩充等）。

**最终交付：方案 A**（`obs_corrector.onnx`，D 组口径 `varianceScaleMax=4.0`、`obsCorrectorMaxBias=2.0`），放行建议沿用 §6。

### 8.7 必须保留的记录（原样归档）

> 端到端在测试站表现优异，但因未归一化 H/V 导致垂直被早停站拖累，最终整体指标不敌方案 A。证明在工程落地中，传统标签监督（方案 A）的鲁棒性更优。

**口径修正说明（不得删除上段，只能并列补充）**：上述记录描述的是 v1（裸 3 维归一化）的实验现象——v1 在完全留出的测试站上确实两项都好（H 133.6 / V 304.1，优于生产 D 的 137.5 / 317.8），整体却被 `…156203` 的垂直回归拖垮。v2 按该诊断做了 H/V 各自归一化 + `scale_max` 收紧，**结果反而更差**（测试站也转为变差），因此「未归一化」只是 v1 的直接诱因，**根因是端到端范式在本场景下缺少方案 A 的标签先验**：方案 A 用 `median_{(epoch,frq)}(before) − before` 把「同历元同频点的共模偏差」显式交给模型，等价于给了它一个物理上正确的解耦方向；端到端只有坐标残差，在单个早停站主导验证集时无法分辨「该降权」与「该改正」。这条记录的工程价值在于：**范式选择的判据必须是同口径真实配对，而不是离线代理指标或单站表现。**

**补充（完整归因见 §8.9）**：上段的「鲁棒性更优」在 §8.9 中被进一步量化为两条可检验事实——① **不稳定**：仅重加权目标函数（H/V 各自归一化）即导致整体垂直摆动 7.4%、测试集垂直摆动 17.3%；② **指标背离**：离线坐标 Loss 在早停站改善 75.1%，同站真实垂直 RMS 反而恶化 +80.5 cm。因此「方案 A 鲁棒性更优」的准确含义是：**方案 A 的收益可预测、可复现、且离线指标与交付指标同向**，而 E2E 三者皆不满足——尽管 E2E 本身有效（§8.9.1）。

### 8.9 客观可用性评估：E2E 是「有效但不可控」

> 本节回答一个与 §8.6 不同的问题：**E2E 是不是一个失败品？** 答案是否。它**技术上可用**（相对不注入显著变好：3D −14.0%、H −17.8%，链路契约完全正常），但**产品上不可交付**（收益对目标函数形式过度敏感，且训练指标与交付指标会反号）。因此处置是**保留为实验 provider**，而非删除。

#### 8.9.1 相对「完全不注入」基线，E2E 的精度类指标全面更好（唯一例外：绝对错固数）

补入 3D RMS 与绝对计数（此前各节只列 H/V 与比率，绝对数会掩盖「固定更少」的假优势）：

|---|---|---|---|---|---|---|---|
| A（不注入） | 170.3 | 319.9 | **362.4** | 23.47% | 13.65% | 4,331 | 31,735 |
| 生产 C | 147.9 | 266.1 | 304.4 | 25.48% | 12.67% | 4,366 | 34,448 |
| 生产 D | 146.2 | 265.6 | **303.2** | 25.55% | 12.42% | 4,290 | 34,542 |
| e2e-v1 C | **140.0** | 278.3 | 311.6 | 24.68% | 13.19% | 4,403 | 33,373 |
| e2e-v1 D | 142.5 | 280.2 | 314.4 | 24.62% | 12.66% | 4,214 | 33,284 |

| e2e-v2 D | 149.0 | 300.8 | 335.7 | 24.49% | 12.38% | 4,101 | 33,113 |

- 相对 A 基线，**e2e-v1 C 的 3D 从 362.4 → 311.6 cm（−14.0%）**，H −30.3 cm（−17.8%），固定率 +1.21 pp，错固率 −0.46 pp。

- 因此 E2E **不是无效方案**：它在水平方向给出了真实、可复现的增益（5/6 站水平更好，见 §8.5）。
- **唯一例外**：e2e-v1 C 的绝对错固数为 4,403，高于 A 的 4,331（+72），原因是它多固定了 1,638 个历元；这不构成「更不安全」的结论，但也不构成安全优势（详见 §8.9.5）。

#### 8.9.2 剔除「基线即不可用」站后，v1 是双赢（敏感性分析）

`…156203` 在 A 组基线的错误固定率就是 **48.66%**，§4.5 已判定其「即便在 A 组也不具备可用性」，但它占 **21,922 / 135,198 = 16.2%** 的历元。按历元数加权重算 RMS（RMS 可按权重精确合成）：

| 组 | 全 6 站 H/V (cm) | 剔除 `…156203`（5 站 / 113,276 历元） |
|---|---|---|
| 生产 D | 145.7 / 265.2（3D 302.6） | 136.9 / 246.8（**3D 282.3**） |
| 生产 C | 147.4 / 265.7（3D 303.9） | 138.6 / 247.8（3D 283.9） |
| e2e-v1 C | 139.5 / 277.4（3D 310.5） | **127.7 / 240.1（3D 272.0）** |
| e2e-v1 D | 142.0 / 279.3（3D 313.3） | **129.1 / 241.0（3D 273.4）** |
| e2e-v2 D | 148.5 / 300.2（3D 335.0） | 136.9 / 271.6（3D 304.2） |

> 口径说明：本表两列**均按历元数加权**合成（`RMS = sqrt(Σ n_i·r_i² / Σ n_i)`），故「全 6 站」列与 §8.4 的跨站 RMS 存在 0.2~0.5 cm 的聚合方式差异（例：生产 D 在 §8.4 为 146.2/265.6，此处加权为 145.7/265.2）。两列同法，对比有效，结论不受影响。

- 在 5 个可用站上，**e2e-v1 C 相对生产 D 是双赢**：H −9.2 cm、V −6.7 cm、3D −3.7%（272.0 vs 282.3）。
- **「整体不达标」这个结论实际上由单个基线即不可用的站决定**，这一点必须如实记录，不能只写「E2E 不敌方案 A」。
- **但该分析属 post-hoc，不得反推判据**（§4.5 已立规：口径变更须走新决策记录，不得事后追认）。同一把尺子对方案 A 与方案 B 必须同样适用，故交付结论仍取整体口径。

#### 8.9.3 稳定性不足（最硬的否决理由）

v1 → v2 仅改「Loss 归一化方式 + `scale_max`」，**数据、seed、架构、切分全部相同**：

| | 整体 H (cm) | 整体 V (cm) | test 集合 V (cm) |
|---|---|---|---|
| e2e-v1 D | 142.5 | 280.2 | 304.1 |
| e2e-v2 D | 149.0 | 300.8 | **356.6** |
| 摆动 | +6.5 | **+20.6（+7.4%）** | **+52.5（+17.3%）** |

这次改动**本意正是修正垂直**，结果垂直恶化 20.6 cm、测试集垂直恶化 52.5 cm。**可交付模型不应在同等数据上对目标函数重加权如此敏感**——它说明训练信号信噪比不足，选到的是「本次优化的落点」而不是「规律」。

#### 8.9.4 离线训练指标与真实指标**符号相反**（最有价值的发现）

| 项 | v1 在验证集（即 `…156203`） |
|---|---|
| 离线坐标 Loss 改善 | **75.1%**（1.7249 → 0.4298） |
| 同一站在 Java 载波 RTK 的 V RMS | 344.9 → **425.4 cm（+80.5 cm）** |

**离线代理指标在「用来早停的那个站」上大幅改善，真实指标在同一站大幅恶化。** 这直接证明：可导 WLS 的码残差坐标 Loss 与 Java 侧载波 KF 的 H/V 误差**不是同一个量，甚至不是单调关系**。

后果：**E2E 无法用离线指标做模型选择**，唯一可靠判据是真实配对（每轮约 15 min × 576 run）。这使「调参迭代」在经济上不可行，也是本轮同意停止的实质原因，而不是「差一点点」。

#### 8.9.5 「绝对错固数最低」是固定更少，不是固定更准

e2e-v2 D 的绝对错固数 4,101 为全表最低，但分解后：

- 绝对固定数 33,113，比生产 D（34,542）**少 1,429**；
- 错误固定率 12.38% vs 12.42%，**只低 0.04 pp**；
- 即少固定的那 1,429 个历元中错误占比约 **13.2%**，与基线均值持平。

**「绝对错固数下降」几乎完全来自固定率下降 1.06 pp，而非固定得更准。** 用 1 pp 固定率换 35.2 cm 垂直，对测量型场景是坏交易，不构成安全优势。

#### 8.9.6 处置：保留为实验 provider（默认关闭，仅显式注入）

| 用途 | 结论 | 理由 |
|---|---|---|
| 生产默认开启 | **不可以** | 不稳定（§8.9.3）+ 指标背离（§8.9.4） |
| 替换方案 A 作为交付物 | **不可以** | 判据未过（§8.4 / §8.6） |
| **同一 SPI 开关下的实验 provider**（默认关闭、仅 `AiHooks.install(provider)` 显式注入） | **可以** | 契约完全一致（`[batch,17]→[batch,2]`、钳位逐位对齐）、Java 侧零改动、ONNX 仅 8 KB，只换模型文件 |
| 作为**研究基线 / 对照组** | **可以** | 已证明「坐标反传」能带来真实水平增益（5/6 站水平更好），该信号值得后续利用 |
| 用于**模型选择 / 早停** | **不可以** | 见 §8.9.4 |

**正式表述（写入放行口径）**：端到端（E2E）作为一个**「有效但不可控」的实验 provider 予以保留**——默认关闭，仅允许显式注入，**不承担任何生产交付责任**，不得作为方案 A 的替代或默认回退目标。其产物 `obs_corrector_e2e.onnx` / `.norm.json` 与方案 A 并存归档，Java 侧通过 `-Dpairing.model` / `-Dpairing.norm` 切换，代码路径零差异。

#### 8.9.7 提升 E2E 交付能力的四个前置条件（下一阶段立项前提）

在**不改变 §8.1 判据**的前提下，若要将 E2E 从「实验 provider」升级为「可交付候选」，必须先满足以下四条；**缺任一条不得重启调参**：

1. **至少 3 个独立验证站**——当前 `val` 只有 1 个站（`…156203`），且该站在 A 组基线即不可用（错固率 48.66%），导致早停决策被单站主导。要求验证集覆盖 ≥3 个独立站、且剔除任何「基线不可用站」后仍满足判据。
2. **3 个 seed 稳定性证明**——同一配置至少 3 个随机种子，要求整体 H/V RMS 的**极差 ≤ 2%**（以生产 D 组为参照）。本轮 v1→v2 的 7.4%（垂直）/ 17.3%（测试集垂直）摆动即反例。
3. **预注册判据**——判据、口径（整体 vs 剔除不可用站）、统计量必须在训练前落盘（如 `docs/` 下的决策记录），**禁止看到结果后调整口径**（§8.9.2 的敏感性分析只能作解释，不得作判据）。
4. **真实配对驱动的选型闭环**——把「训练 → Java 双跑配对 → 统计」压到可迭代量级（当前单轮约 15 min × 576 run），并明确「离线指标不得参与模型选择」（§8.9.4），否则迭代成本与结论可靠性不可兼得。

**立项要求**：以上四条须作为**下一阶段立项的前提条件**记录；未满足前，E2E 维持实验 provider 身份，方案 A 继续作为唯一交付方案。

### 8.10 边界探索：激进钳位（aggressive）四向对照（**场景限定，不改变处置结论**）

> 本节是**已执行**的边界探索，回答两个问题：① 把 `varianceScale` 下界从 1.0 放宽到 0.5 能否回收错固；② 方案 A 与方案 B 在同一激进口径下谁更优。**它不改变 §8.6 / §8.9.6 的处置**（E2E 仍为实验 provider、方案 A 仍为唯一交付），理由见 §8.10.7。

#### 8.10.1 实验设计

| 配置 | 方案 | 训练目标 | 训练侧 `scale_min` | 推理侧钳位 |
|---|---|---|---|---|
| **A 激进** | 方案 A | sd 标签监督 | 无此参数（模型输出天然 ≥ 1.0） | `[0.5, 4.0]` |
| **B 保守** | 方案 B | 坐标 Loss | 1.0 | `[1.0, 4.0]` |
| **B 激进** | 方案 B | 坐标 Loss | 0.5 | `[0.5, 4.0]` |

- A 的「保守 → 激进」是**同一模型只改推理钳位**；B 的是**两个独立模型**（仅 `scale_min` 不同，数据、切分、seed、`bias_max`、`hidden`、`lr`、`batch_runs` 全部一致）。
- `--scale-min` 是本次为方案 B 新增的训练参数（[train_e2e.py](file:///D:/code/rtklib_java/rtklib-ai/training/obs_corrector/train_e2e.py)），训练侧与推理侧钳位同步。**此前的「激进模式测试」在方案 B 上是空操作**：模型 `scale_min` 恒为 1.0，推理放宽到 0.5 后没有任何样本落在新下界内，所以「A 激进无效果」的历史结论不能直接套用到方案 B。
- **评估口径（与 §8.4 不同，禁止跨节比较）**：真值取外部独立文件 `truth.csv`；错误固定判据 0.20 m；RMS 按历元数加权合成；泛化口径取**测试站 2 站 × 4 日 = 192 run / 45,501 历元**（站级与站内日级两层切分均未参与训练与早停）。§8.4 的 H/V RMS 用自动真值 + 跨站算术聚合，故两节绝对值存在 1~6 cm 差异，只能各自内部比较。
- 本节**只统计水平 H**，未复核垂直 V。

#### 8.10.2 总概况

- **A 激进 vs A 保守：无区别，空操作。** 假固定 −11（t = −0.41）、正确固定 +14（t = +0.25）、H 加权 1388 → 1387 mm，全部落在噪声内。原因是方案 A 的模型在真实特征上几乎不输出 < 1.0 的 scale（离线 `scale_frac_at_floor` 仅 7.3e-6），放宽推理钳位没有可作用的样本。
- **B 激进 vs B 保守：纯赚。** 假固定 −47（−17%）、正确固定 +1（不丢）、精度 −2.3%，三项全正。机制明确：B 激进模型 `scale_frac_at_floor` 达 **36.4%**，钳位真实生效。
- **A vs B：是交换，不是强弱。** A 赢可用性（净可用多约 3%），B 赢精度（−5%~−7%）与精确率（+0.0~+0.3 pp）。

#### 8.10.7 限定与**不改变的结论**

1. **本节不推翻 §8.6 / §8.9.6。** §8.6 的判据是**训练前预注册**的「整体 135,198 历元的 H 与 V 同时优于生产 D 组」；本节 (a) 只统计 H、未复核 V，(b) 用的是新训练的 `e2e-cons` / `e2e-aggr` 两个模型实例而**不是** v1 / v2，(c) 真值、聚合方式与 §8.4 均不同。因此本节只能作为**方案 B 能力边界的补充证据**，不能替代 §8.6 的交付判定，也不得被引用为「E2E 已达交付水平」。
2. **本节强化的是 §8.9 的「有效但不可控」判断**：方案 B 在精度维度确有真实优势（与 §8.9.1「相对不注入全面更好」同向），但可用性系统性低于方案 A，且优势幅度对钳位与训练目标敏感——这正是「可控性不足」的又一表现。
3. **统计显著性**：除「A 激进无效果」（差异本身落在噪声内）与「B 激进方向全正」外，所有配对 t 值绝对值在 **0.4~1.7**，**无一项达到 0.05 显著**。B 相对 A 的净可用损失方向一致但仅约 3%，且 run 间同站同日高度相关，t 值本身偏乐观（有效样本量约为 run 数 192，而非历元数 45,501）。**结论应读作「方向明确、幅度待更多日期/更多站点验证」。**
4. **适用场景边界**：本探索全部建立在纯北斗、超短基线、静态站、4 个观测日的数据上（见附录 B 第 1 条）。激进钳位放宽 `varianceScale` 下界会直接放大「过度自信」风险，在动态、长基线或多星座场景下**必须重新评估**，不得直接沿用本节的「B 激进可用」结论。
5. **产物**：`rtklib-ai/training/out/e2e-cons/`、`rtklib-ai/training/out/e2e-aggr/`、`rtklib-ai/training/out/aggressive/`；配对原始数据 `data/fix-validator/pairing-e2e-a576-cons/`、`pairing-e2e-a576-aggr/`、`pairing-a576-cons/`、`pairing-a576-aggr/`。
